# 教师账号安全 Phase 0 与 Phase 1 首批实施记录

基于当前项目的 Go API Gateway、PostgreSQL / Redis、React 管理端、既有 RBAC 和审计链路实施。没有另建独立身份服务，也没有假设项目已接入短信供应商或学校 IdP。

## 已实现的链路

- 教师管理端用姓名、手机号、可选教职工号和组织职责创建 `invited` 账号，不再收集管理员代设的最终密码。邀请有效期 48 小时；重新生成会使此前未消费的邀请失效。
- 本人通过 `/activate` 设置至少 15 个 Unicode 字符的密码。服务端先验证链接再计算密码摘要，事务中一次性消费链接、激活账号、递增安全版本并撤销旧会话。邀请与恢复页不被已有浏览器会话遮住；完成后返回已确定的学校登录入口，仍需正常登录。
- 全局登录入口保留学校代码；`?tenant=学校代码` 和 `/school/学校代码` 专属入口隐藏学校代码输入。服务端支持手机号、教职工号、原账号；旧 `tenant_code + username` 协议仍可使用。
- 手机号按可确定的 E.164 格式归一化。租户内手机号及教职工号分别唯一；跨字段标识同时命中不同活跃账号时拒绝登录，不按任意顺序挑选账号，也不跨租户猜测身份。
- 密码摘要新增 Argon2id PHC 格式（19 MiB、2 次迭代、并行度 1）。旧 bcrypt 摘要在成功登录时条件更新为 Argon2id。旧短密码仍可验证，新建、激活、修改和恢复使用长密码策略；上限为 1024 UTF-8 字节，前后端长度规则一致。
- 登录限速分为账号、来源和标识／来源组合三层；已识别账号以服务端用户 ID 统一手机号、工号和原账号的计数，未知账号以归一化标识计数。手机号等价写法及 IP 地址做归一化。正常登录不会清空来源层的密码喷洒计数。沿用 Redis 和内存降级链路。
- 管理员“协助恢复”产生 30 分钟一次性链接；只能恢复其组织范围内、其角色有权管理的活跃账号，不能恢复自己或越权恢复更高级角色。链接绑定签发时的安全版本，改密或停用会使此前未使用的恢复链接失效。本人设置新密码后全部原有会话失效。
- 停用账号递增 `security_epoch` 并撤销会话；重新启用不会恢复旧会话。待激活账号不能经“停用再启用”绕过激活。登录签发会话绑定验证时的安全版本，防止密码恢复或停用后的旧凭据在途登录重新签发会话。
- 个人账号安全页展示设备、改密和最近安全活动。活动复用既有审计数据，只返回事件 ID、类型、风险级别、粗粒度设备和时间；不返回原始 IP、User-Agent、请求 ID 或审计载荷。
- 登录页可显式选择“学校公共电脑”。公共电脑与“常用电脑”互斥，只能创建浏览器会话；服务端默认设置 4 小时绝对有效期且不写持久 Cookie。前端在整个会话中持续展示公共电脑标识与立即退出入口；15 分钟无操作或关闭／离开页面时调用 `/api/v1/auth/lock` 在服务端锁定当前会话，普通业务接口会拒绝已锁会话。工作区保留未保存状态，用户通过 `/api/v1/auth/reauthenticate` 快速重新验证后解锁，成功时写入 `reauthenticated_at`；失败和成功尝试均进入分层限速与审计。退出时清空当前用户的本地草稿／未完成命令和内存查询缓存。
- 近期认证只保护可能导致账号接管、正式成绩对外生效或平台级机构状态发生重大变化的关键操作，默认窗口为 60 分钟。正式成绩发布和成绩版本回滚、管理员协助恢复账号、撤销其他用户全部会话，以及 Tenant 创建或状态变更仍由服务端 `RequireRecentAuth` 保护。人员建号、邀请重发、账号停启、成绩准备与确认、复评版本生成、发布门禁与 waiver、成绩／报告／审计导出和模型治理继续执行权限、资源范围与审计检查，但不要求重复输入密码。过期时关键操作返回稳定的 `428/recent_auth_required`；管理端对已登记的关键操作显示具体原因，验证成功后自动继续原操作一次，再次返回 428 时停止，避免循环。公共电脑 15 分钟无操作锁定、改密和 MFA 专门验证流程不受此窗口影响。`RequireAuthLevel` 已提供后续 MFA／企业 IdP 的认证等级边界，但密码会话目前仍只有等级 1。
- Phase 1 动态风控首批基础以 `shadow` 模式接入登录链路。策略 `login-rba-v1` 按账号滥用、凭据生命周期、设备上下文、网络上下文四个独立信号族计分并分别封顶；校园 NAT／IP 前缀变化不能单独触发高风险，冷启动账号不因设备或网络“首次出现”受罚，只有至少 3 条成功历史且复合信号达到阈值才产生 `step_up` 建议。当前建议只写入会话、风险事件和审计，不阻断教师登录。
- 普通浏览器登录使用独立的 HttpOnly、SameSite=Lax 不透明设备 Cookie，服务端只存 SHA-256 摘要。密码观察到的设备仅为 assurance level 1“已识别设备”，绝不等同 MFA 或可信设备；公共电脑不读取绑定并主动清理 Cookie。改密、恢复、停用和撤销全部会话会同时撤销服务端设备绑定。
- `auth_session` 持久化风险等级、动作、分数、证据质量和策略版本；`auth_risk_event` 保留可解释的原因码及信号族分数，`auth_trusted_device` 保存最少化设备绑定。两张新表启用并强制租户 RLS。应用在写入时按用户保留最近 20 条登录画像并清理 180 天以前的历史，设备绑定默认 180 天过期。
- 未分配班级的教师仍能管理自己的账号和会话。仅个人账号接口允许空业务范围；试卷、成绩、题库等业务接口保持原有失败关闭的权限边界。
- 激活／恢复链接只持久化 SHA-256 摘要；明文只在生成时返回。相关响应禁止缓存，前端取到令牌后清除地址栏查询参数；审计不记录链接或密码。

## 项目兼容性与边界

机构初始管理员和旧 API 的直接设密建号入口保留，受相同新密码策略约束。教师管理 UI 已默认走邀请。没有自动合并历史账号，没有把手机号当作“已验证的短信身份”，也没有自动登录恢复后的账号。

`000143_auth_identity_security_epoch.sql` 增加身份、生命周期、安全版本、会话认证上下文、激活及恢复表。历史手机号只在格式可确定且租户内无冲突时回填；冲突保持未绑定，需管理员显式核实。已有活跃／停用账号回填激活时间。表约束使用租户与用户的组合外键防止跨租户引用。迁移文件不代表已执行生产迁移。

## 部署注意事项

1. 先备份并在测试环境执行项目正常迁移流程，确认历史手机号冲突及索引建立情况。当前工作树还包含其他业务迁移，应以项目生成的最新 schema version 为准，不能只部署本文件后声称整个 schema 已升级。
2. 后端兼容旧登录请求，先升级后端再更新管理端。旧二进制不能读取新的 Argon2id 摘要；避免将旧节点与已开始写入 Argon2id 的新节点混用，回退必须准备兼容 Argon2id 的版本。
3. 邀请和恢复链接通过可信渠道交付，管理员先核对本人身份。生产入口使用现有 HTTPS 与安全 Cookie 配置；链接包含 bearer secret，网关／监控不得记录其查询参数或请求体。
4. 保留受控的初始管理员恢复入口，验证 Redis 不可用时的降级行为、会话撤销和审计写入；本记录不代表真实学校账户恢复演练已经完成。
5. 公共电脑会话时长由 `EDUGRADE_PUBLIC_SESSION_TTL` 配置，默认 `4h`。它是服务端绝对上限，不应配成长期会话。
6. 关键操作的近期认证窗口由 `EDUGRADE_RECENT_AUTH_TTL` 配置，默认 `60m`。它只覆盖正式成绩发布／回滚、账号恢复、撤销他人会话和 Tenant 级重大操作；调整时应同时评估这些边界。公共电脑无操作锁定仍固定按独立的 15 分钟交互策略执行。
7. 动态风险默认由 `EDUGRADE_AUTH_RISK_MODE=shadow` 开启观测，也可设为 `off`。在业务升阶与恢复策略形成完整闭环前，配置加载仍拒绝 `enforce`；可选 TOTP 管理试点不代表强制策略就绪。设备 Cookie 名和最长绑定期分别由 `EDUGRADE_DEVICE_COOKIE_NAME`、`EDUGRADE_DEVICE_BINDING_TTL` 配置，后者限定在 24 小时到 365 天。
8. 可选验证器管理试点默认关闭，部署和边界见 [TOTP 与操作级挑战管理试点](teacher-account-security-mfa-pilot.md)。注册确认、一次性恢复码保存及两种自管理操作的挑战现已接入管理端账户安全页，但不改变普通登录或业务授权；研究与强制策略门槛见 [交互与风控研究](teacher-account-security-mfa-ux-research.md)。

## 验证

新增内存与 HTTP 回归覆盖 Argon2id、bcrypt 登录升级、手机号格式、标识歧义、分层限速、邀请重发、链接过期／并发一次性消费、恢复权限、旧会话与在途旧登录失效、个人账号与业务权限分离、活动脱敏，以及公共电脑的模式互斥、独立会话类型、可配短有效期、服务端锁定与非持久 Cookie。近期认证回归覆盖新登录、时间过期、未来时间异常、认证等级不足、密码重新验证刷新时间、关键路由在 stale session 下返回 428，以及日常管理路由在同一条件下不返回 `recent_auth_required`。动态风险回归覆盖冷启动不惩罚、校园网络单信号不升阶、信号族封顶、复合强信号才建议升阶、浏览器绑定仅作“已识别”而非 MFA、公共电脑清理绑定 Cookie、密码重新验证不降低风险，以及用户画像的数量／时间保留边界。前端回归覆盖公共会话映射、当前用户本地数据清理、428 升阶事件，以及显式关键操作的成功直通、验证后单次自动重试、密码错误、取消和循环保护。

新增公共电脑锁定并发回归：在途验证不能撤销验证开始之后的新锁定；在锁定之后发起的验证才可解锁。关键操作的旧成功回执不能绕过过期认证或已撤销权限；普通导出回执仍在每次重放前检查当前权限，但不再检查认证时间。

`internal/server/e2e_auth_security_test.go` 使用项目现有辅助函数创建并清理随机隔离 PostgreSQL 数据库，验证历史数据迁移和实际 SQL 事务链路。运行方式：

```powershell
$env:EDUGRADE_E2E_DATABASE_URL = '<仅用于隔离测试的 PostgreSQL 管理连接>'
go test ./internal/server -run '^TestTeacherAccountSecurityE2EWithPostgres$' -count=1 -v
```

该连接需要创建测试库权限；测试会自行创建随机 `edugrade_e2e_*` 数据库并在结束时删除，仅使用合成账户。

## 尚未完成的规划

Phase 0 的泄露密码检测目前只有小型常见模板阻止名单，不是完整泄露密码库；来源层没有 ASN 风险服务。安全活动是审计投影，不是完整独立事件中心，部分管理员操作仍只在组织审计中查看。

MFA 安全变更现已具备与凭据事务原子提交的语义 outbox 事实和 append-only 通知待办，解决“因素已变更但通知义务丢失”的双写缺口。待办状态仅为 `awaiting_channel`；现有日志发布器不代表投递，项目仍没有已验证外部联系人、真实通知渠道、回执或退信处理，不能据此声明独立通知已经交付。

Phase 1 / 2 的动态风险强制处置、管理员 MFA、管理员统一下发的共享机房设备策略、批量教师导入、学校 OIDC、WebAuthn、SAML／LDAP 和独立机器凭据尚未完成。动态风险目前只做版本化影子评估与可解释证据留存；`allow_restricted` 和 `step_up` 仍是建议动作，不会改变授权或拒绝登录。近期认证覆盖已识别的高风险路由，尚未替代强制 MFA，也未实现基于具体风险信号选择验证方式的完整 `step-up/start` 挑战流程。会话中的 `auth_method / auth_level / risk_level / risk_action` 是后续演进基础，密码重新验证只刷新认证新鲜度，不会把既有风险降为 `low`。企业身份与 MFA 的现有规划见 `docs/stories/STORY-074-enterprise-identity-mfa.md`。

没有配置短信验证时，不开放看似“已验证手机号”的自助恢复入口；没有真实学校 IdP 和账号映射约束时，不开放 SSO 按钮。后续应先选择真实试点学校与供应商，再实施协议和运维验收。
