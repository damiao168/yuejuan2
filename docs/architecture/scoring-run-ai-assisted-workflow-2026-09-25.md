# 评分轮次与 AI 辅助阅卷：产品流程及交互方案

## 决策与范围

考试的冻结题目策略决定每道题的处理路线，不能由“存在已发布规则”或页面按钮临时改写。`RULE_AUTO` 进入规则/OMR，异常转人工；`AI_ASSIST` 与 `AI_FAST_CONFIRM` 对受支持的主观题产生 **建议分及证据**，同时保留教师复核任务；`HUMAN_PRIMARY`、`DUAL_HUMAN`、`MANUAL_ONLY` 进入人工路线。AI 建议不得直接进入最终分数或成绩发布。这里的 `AI_FAST_CONFIRM` 仍须教师确认，“快”指后续可优化教师操作，不代表自动终审。

这一选择与 ETS 在高风险写作测评中将自动评分配合人工评分的实践一致；微软的人机交互指南要求系统明确能力、允许用户纠错；NIST AI RMF 要求定义并记录人工监督职责。[ETS e-rater](https://www.ets.org/erater/about.html)、[Microsoft Research：Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/)、[NIST AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)。

## 教师端流程

1. **准备**：完成答卷采集、切分、Rubric、题目策略和模型治理配置。评分就绪检查只承诺题块可以进入规则或人工路线；模型服务准入在 AI 批次入队时另行执行。模型不可用不应吞掉人工任务。
2. **预览**：点击“开始评分”后打开路线确认弹窗。逐题显示题号、题型、份数、冻结模式、风险级别、目标路线和原因；顶部汇总规则自动、AI 候选（需另行试改）、其他人工份数。快照读取失败的题目按人工路线展示，并明确提示。
3. **启动与试改**：评分命令以既有幂等键创建 `scoring_run`，服务器按冻结策略生成规则处理或人工任务。对允许 AI 建议的同一题目，教师先选择 5–10 份当前答案版本未开始过 AI 评分的答卷（无已有主观题 AI 运行或 AI 成绩），记录人工基准分，并标出代表性、边界和证据不完整样本，再创建试改。人工基准与样本批次同事务持久化；服务端已接受的试改记录可在刷新或换浏览器后恢复。新增评分运行必须经过试改闸门，直接创建普通批次、单份运行或面板运行不能绕过。
4. **核对与扩批**：样本建议结束后，教师逐份比较人工基准、AI 建议、证据和风险，明确填写停止或扩批理由。扩批使用最新持久版本并重新校验题目、评估快照、Rubric、答案及模型策略，只为同题尚未被批次覆盖的片段创建建议批次。扩批决定与实际批次同事务保存，重试沿用原批次。顶部运行条显示自动确认、待人工和失败数；AI 区显示本轮建议进度。教师仍须在人工任务中查看原答题证据，接受或修改分数后提交；无建议或模型失败时继续人工评分。
5. **异常恢复**：创建/入队部分失败时显示可操作的“重试 AI 入队”，保留已经创建的批次，不重复生成任务。任务执行失败显示失败数并转人工处理；模型失败不能通过重新点击启动评分绕过原有 run。网络响应丢失时，服务端已接受的试改记录与批次可跨浏览器恢复；待确认的原创建命令仅保存在同一浏览器的 `sessionStorage`，在该会话中恢复后沿用原命令重试。
6. **取消**：取消确认文案明确覆盖规则、AI 和人工任务。服务器先将 run 置为 `cancelling`，取消其活跃 worker 任务，确认没有活跃任务后标记关联 AI 批次、人工任务和 run 为 `cancelled`。数据库对关联批次和新 worker 任务实施状态屏障，避免取消竞态重新派发。已生成的历史证据保留供审计，不转为最终成绩。
7. **成绩发布**：人工复核、必要的双评/仲裁、总分核对依次完成；发布时冻结本次可见的分数与反馈，报告只读取这份发布事实。

## 界面状态与文案

| 状态 | 页面行为 | 教师可执行动作 |
| --- | --- | --- |
| 未就绪 | 显示阻塞项及对应修复入口；按钮禁用 | 完成模板、Rubric、题块检查 |
| 可启动 | “开始评分”打开路线预览，不直接隐藏策略 | 核对各题路线并启动 |
| 已启动 | 显示评分轮次、逐卷结果与 AI 建议进度 | 查看原图、进入人工任务、处理异常 |
| 等待试改 | 展示同题候选答卷、人工基准和样本角色 | 选择 5–10 份样本并录入基准分后提交 |
| 样本可核对 | 展示样本差异、证据、风险及已回传用量 | 填写理由后停止或扩大同题建议生成 |
| 试改已作废 | 保留原基准和历史结果，拒绝继续入队或扩批 | 按当前上下文重新建立试改 |
| AI 入队部分失败 | 警示包含失败数量，保留已入队结果 | 重试 AI 入队；人工任务照常处理 |
| 模型执行失败 | AI 区显示失败数，人工任务不关闭 | 人工评分，必要时按治理流程重试模型 |
| 取消中/已取消 | 停止新任务，刷新后仍保留批次审计记录 | 取消中可点“继续取消”；完成后可创建新评分轮次 |

“规则自动”仅指规则路径的正常结果可自动确认；“AI 建议”绝不等于最终成绩。建议分在证据区呈现，不应默认写入教师分数输入框，教师要做出明确操作。高风险题（特别是长文本、数学证据不完整、低置信或冲突）保持人工判定。这也符合 ETS 对异常答卷标记人工复核的做法。[ETS：How the e-rater Engine Works](https://www.ets.org/erater/how.html)。

## 数据及 API 约束

- `exam_question_snapshot.scoring_policy_snapshot_json.mode` 是评分分流的唯一权威；缺失或不支持的模式安全转人工。
- `subjective_grading_batch.scoring_run_id` 是显式关联，原有独立 AI 批次保持 `NULL`。创建关联批次时，所有片段必须有该 run 的待处理人工任务，且其冻结模式允许 AI。相同幂等键必须同时匹配操作者、片段及 run。
- `GET /api/v1/scoring-runs/{runId}/ai-batches` 返回持久批次状态，供跨会话恢复；权限与评分管理一致，按租户隔离。
- `GET/POST /api/v1/scoring-runs/{runId}/ai-trials` 恢复或创建试改；`POST .../{trialId}/enqueue` 恢复服务端保存的样本或扩批批次；`POST .../{trialId}/decision` 保存停止/扩批理由与预期版本。四项操作均要求 `grading:manage`，并验证运行所属租户和学校。
- 迁移 `000196` 为新建运行启用 `scoring_run.ai_trial_required`；迁移前的运行保持旧批次恢复能力。`scoring_ai_trial` 启用强制租户 RLS，不给普通运行角色删除权限，并纳入考试归档只读约束。
- 试改按服务端指纹绑定评估快照、Rubric、参考材料、题目、样本答案及模型策略。刷新、重新入队或决定时发现变化，会持久化 `invalidated` 并取消相关批次；即使命令返回冲突，也保留作废事实。停止和作废会关闭活跃的主观题运行、worker 任务及当前 attempt，迟到回调不得复活已关闭运行。
- 样本成绩带 `trial_sample` 风险标记并要求人工复核，不能进入无风险快捷确认。试改结果只关联本样本批次的实际运行与成绩，不借用历史建议或正式成绩。
- 停止不会清除样本已经接触 AI 的事实：同一答案版本已有主观题 AI 运行或成绩时，不能再次当作独立人工基准；无法识别答案版本的历史成绩也按已接触 AI 处理。取消后尚未创建 AI 运行或成绩的片段仍可重新选择；新的答案版本按其当前事实重新校验。
- 同题扩批最多包含 1000 个剩余片段；超限明确返回 `scoring_trial_expansion_limit_exceeded`，不保存扩批决定或创建部分批次。
- 创建 batch、创建关联 worker task 的数据库触发器读取并锁住父 run 状态；与取消事务共用行锁屏障。取消只清理当前 run 的批次，不根据可伪造的键名前缀关联其他任务。
- 评分结果仍沿用现有候选分、人工分、仲裁、最终分与发布事实链；AI 批次成功只表示“建议已生成”，不表示“教师已确认”。

## 验收与后续边界

已实现并可验证的闭环：冻结策略分流、预览弹窗、人工基准先于 AI 的同题试改、差异核对后的幂等扩批、服务端批次恢复、停止/作废后的任务关闭、教师工作台展示建议及人工确认、发布结果冻结。验收需覆盖模式组合、快照不可读、重复点击、刷新/换浏览器、部分入队失败、答案与策略变更、取消竞态和报告发布后不漂移。

试改仅报告样本中可追溯的差异，人工选择的少量样本不构成准确率或全卷质量的统计保证。耗时与 Token 用量来自实际成绩和用量记录；未回传时显示未知，不能当成零成本。Token 数不等于费用，当前不提供可据以放行的费用估计或节省承诺；扩批仍受现有模型治理和人工复核要求约束。

已追加的产品流程：`DUAL_HUMAN` 启动前要求同校至少两名在岗阅卷员，按稳定名单轮转创建互盲双评任务；两分相同自动形成双评终审分，两分不一致进入仲裁，仲裁完成后才计为本轮人工已确认。取消会关闭待仲裁任务，并使本轮题分失效。`AI_FAST_CONFIRM` 提供教师端快捷确认抽屉：仅检查当前队列前 20 份分配给本人的任务，列出 R1/R2、非数学、无评分细则点、无风险标记、含非空作答证据且置信度至少 0.95（若冻结策略阈值更高则从其值）的建议；点击某份后原图、证据和确认框在该份下方展开，教师必须逐份查看、逐份勾选，再批量提交。每份仍调用普通人工提交命令，单份失败不会回滚其他已提交分数，界面显示部分成功并要求重新核对。其余题走完整工作台。

AI 批次在页面重载后从服务端恢复；试改批次入队失败时恢复同一试改的服务端批次，新运行不能用普通重试批次绕过试改决定。保留原批次及模型证据，界面显示累计失败与操作入口。仍需真实模型、扫描硬件及生产对象存储的环境验收；服务端独立的队列告警和按任务的重试治理可继续完善。是否允许某些低风险主观题免人工终审，须单独形成测量与治理决策，当前实现一律要求教师确认。
