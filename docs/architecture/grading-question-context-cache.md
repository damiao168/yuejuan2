# 阅卷固定上下文前缀

## 本轮实现

本轮调整真实模型请求的材料顺序，让同一题、同一角色的固定材料保持在学生作答之前。适用于通用文本评分、数学 v2 及各学科共用的图像 v3 比较流程。选择、填空中由确定性规则完成的计分仍不需要模型缓存。

这里只复用供应商能够识别的共同前缀计算，不在应用中缓存跨学生评分结果，不新增 Redis 或 KV 服务。供应商是否命中、达到多长前缀才命中、是否计费优惠，不能由消息相同直接推出。

| 路径 | 固定部分 | 每份答卷独立部分 | 版本选择 |
| --- | --- | --- | --- |
| 通用文本 | 系统规则、学段、学科题型、角色、题干、量规和输出约束 | 学生文本、OCR 置信度、修复原因 | `subjective-governed-cn-subject-routing-v7-prefix` |
| 数学 v2 | 系统规则、角色、学段、冻结题干、量规、参考资料及按 ordinal 排列的参考图 | 学生证据、作答图、修复原因 | 同上；同时更换材料包装摘要 |
| 图像 v3 比较 | 系统规则、角色、题目、冻结量规和参考答案 | 冻结学生观察、本人的作答裁图 | `frozen-rubric-comparison-v3-20261106-prefix-v1` |

通用文本新布局仍输出同一 JSON 对象，只调整固定字段的序列化顺序。数学证据 schema 仍枚举本份学生的合法证据 ID；若供应商将 schema 放在消息前面，这些变化可能减少实际前缀命中。不能删去证据约束来提高命中率。

图像首轮盲读不接收量规和答案，也没有改动观察提示词版本。A/B 和仲裁仍独立读取原图与冻结依据，不接收其他角色的分数。所有采分点、证据归属和确定性结算门禁保持生效。

## 版本与恢复

旧文本 V6 清单及原数学消息函数保持原字节，旧数学材料包装摘要仍为 `59283668d2e1fb482908830437831202b78883ab2e34df788d478c82ff61fce4`。新清单由 `scripts/evals/check_grading_prefix_manifest.py --write` 从校验通过的原提示词生成，不修改原 Markdown。生成清单不等于通过新版本模型评测或审批。

图像任务创建时把比较版本保存在既有 run 中，数据库已有不可变约束。执行、各评分角色和结果结算都校验同一冻结版本。开启或关闭新布局只影响后来创建的任务，不能把已经排队的任务换版；未知版本和供应商返回的错误版本均拒绝。旧图像版本继续支持。

数学能力接口公布实际选中布局的包装摘要，材料许可消费再次核对。新布局不能冒用旧包装或旧 prompt 范围的审批。文本部署仍需网关与 worker 配置版本一致。

## 用量诊断

沿用 `execution_diagnostics.usage`，增加可选的 `cache_write_input_tokens` 和 `uncached_input_tokens`。不增加数据库迁移，也不改现有 `ModelTokenUsage` 账本含义。

只读取适配器明确认识的供应商字段；缺失为未知，明确返回零才记为零。只有拆分信息完整且合法时才计算剩余未缓存输入，不把缺少写入统计视为零。重试或观察加比较的累计用量逐次相加，不重复加入上一轮累计值；缺失的可选统计和溢出不能伪装成完整合计。接口中的整数边界仍为精确 int64。

新增统计默认关闭，因为旧网关严格拒绝未知字段。该开关仅控制诊断字段，不会开关供应商自身缓存。诊断不增加题文、学生作答、图片、凭据或供应商私有思考正文。

## 配置与启用顺序

默认保留旧消息布局和现有部署行为。本轮没有调用真实供应商、变更数据库审批或启用运行环境开关。

1. 先升级 API 网关，使其能够解码新增诊断字段。
2. 升级 grading-agent，确认同时支持旧图像版本、新图像版本与新文本清单。
3. 可以开启 `EDUGRADE_GRADING_CACHE_USAGE_DIAGNOSTICS=true` 收集供应商已报告的读写拆分；供应商没有报告的字段仍缺省。
4. 合成样本及质量验收通过后，以 `EDUGRADE_AI_IMAGE_PREFIX_CACHE_ENABLED=true` 为新图像任务选用前缀布局。设回 false 只影响新任务，已冻结的新版任务继续用新版执行。
5. 通用文本和数学如切换 V7，Compose 配置须令 `EDUGRADE_AI_PROMPT_VERSION=subjective-governed-cn-subject-routing-v7-prefix`；Compose 会映射到 worker 的 `EDUGRADE_GRADING_PROMPT_VERSION`。独立部署时，网关和 worker 的这两个变量都要设为同一 V7 值，并使用与实际提示版、包装摘要、学科题型和模型部署匹配的新评测及许可。不要直接覆盖旧版本的批准记录。

两个 `.env.example` 和 Compose 已登记上述开关。这里的“默认关闭”是兼容旧 worker/网关和保留已批准评分输入的部署边界，不代表已上线验证过收益。

## 验收与后续

离线测试用不同合成学生检查固定前缀相同、动态尾部不同；变更角色、题干、量规和参考材料后前缀变化。通用文本覆盖已登记的学科题型和初高中路径，数学保留每份证据的 schema，图像通过 OpenAI 兼容和 DashScope 的实际消息转换进行模拟验证。另验证旧版本消息及包装摘要、不同版本许可拒绝、队列期间开关切换、分角色结算、重试累计和未知用量。

这些测试不提供真实评分质量、成本或时延结论。实际验收应在相同模型与合法样本上比较冷/热请求，记录已知输入 token 中缓存读取占比、字段覆盖率、供应商耗时 P50/P95、结构化与证据通过率、评分差异及人工复核比例。未经测量不承诺提速百分比。

同题任务聚集、显式供应商缓存参数、预热、租户级缓存盐与自建 KV 系统仍属后续选择：先证明当前自然前缀有收益，再按实际端点能力实现，不能根据模型显示名称推断支持。研究对照见[核查与实施方案](../../reports/grading-question-context-cache-design-2026-11-06.md)。
