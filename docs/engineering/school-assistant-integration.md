# 学校助手接入与变更维护

学校助手采用统一 AI 对话、协议无关业务工具和薄接入层。原业务服务负责进度、统计和发布规则；模型理解提问并选择工具，服务端负责范围验证、读取结果、整理来源及提供导航。新增页面或修改菜单时，不重新实现一份 AI 专用业务规则。

## 1. 三个稳定边界

```text
统一对话 → 模型编排 → 工具注册与逐次授权 → 原业务服务
                        ↓
                  事实、来源、受控导航 → 模型回答与界面
```

- 领域规则只有原业务服务一份。考试投影与助手共用 workspace.Service；发布诊断共用完整 releasegate 求值，不调用会追加证据的 Preview。
- 适配器只转换字段、可用状态、单位和显示结构；它不能重新决定成绩是否可发布、给学生改分或扩大访问范围。
- 模型消费真实 facts、blocks、sources、actions，UI 显示回答、查询进度与来源。业务问题 code 是开放字符串；新增问题仍保留来源说明。

当前工具为考试检索、考试进度和学生端发布诊断；原 M0 查询仅保留兼容。这里的扩展约定不代表成绩分析、题库或其他模块已经接入。工具登记在 `tools.go`，模型适配在 `modelgovernance/managed_agent*.go`，循环和预算在 `conversation*.go`，新增业务能力通常不修改对话循环。

当前无需 MCP。未来外部 AI 客户端接入时，在同一工具执行层外增加 MCP 适配；领域服务和模型编排不依赖该协议。

## 2. 发生变化时改哪里

| 业务变化 | 最小修改位置 | 需要验证的行为 |
| --- | --- | --- |
| 菜单顺序、分组、页面展示文案 | 原菜单/页面配置 | 入口仍可访问；通常不改读适配器 |
| 页面布局、按钮位置 | 原页面入口的挂载位置 | exam/section 上下文仍准确，打开不自动查询 |
| 现有服务新增阻塞或警告 code | 通常不用改主查询和 UI；有新处理入口时增加导航映射 | 新问题不会被过滤；主判断来自原完整求值 |
| 业务路由或 section 改名 | 前后端集中导航映射，以及原路由注册 | 同考试目标、权限校验和未保存拦截仍生效 |
| 筛选参数新增/改名 | 页面上下文适配与目标页参数消费 | 返回页面准确恢复筛选；未消费参数不生成“直接定位”入口 |
| 服务返回字段或单位变化 | 该模块读适配器、契约、正式生成 SDK | 缺失不变零，单位与统计口径不变或明确更新 |
| 业务规则变化但服务结果结构不变 | 原业务服务；必要时更新指标说明 | 助手读取新结论；不维护独立规则副本 |
| 权限、学校/班级范围变化 | 集中任务权限及原资源范围服务 | 查询前重新验证；授权之前不读取统计 |
| 新业务模块或新任务 | 新增窄读端口/适配器、任务登记和必要契约 | 先只读、先过滤再聚合、来源可解释；不复制所有旧模块 |

“无需大改”依赖边界稳定，不表示可以忽略业务含义变化。统计单位、发布渠道或权限改变时必须核对适配器和回归测试。

## 3. 向后兼容规则

1. 新增 issue code 保留来源的 message、count 和严重度。只有已知且已授权的 action_route 才生成处理入口；未知入口不拼任意 URL。
2. 主协议的 type/status 等核心字段由 OpenAPI 约束。新增模块能力通过正式契约生成 SDK，再运行类型检查；不能在前后端分别维护不一致的整套 DTO。
3. 新增可选字段优先采用有明确空值含义的方式。不把缺失、无样本、读取失败当成 0。
4. 数据来源降级时保留来源状态和限制，不允许模型补齐未核实的业务数字。
5. 路由变化只更新导航适配，不把 URL 写进提示词、模型输出或每个结果组件。
6. 能力列表只供界面展示；请求时仍检查当前身份、业务权限和 body 中的资源。

## 4. 最小回归清单

- 原页面与助手对相同考试得到相同业务规则结论。
- 新增未知问题类型仍显示；未知处理入口不会导致整个结果失效。
- 学校/班级限制不会因 parent school ID、菜单可见性或客户端提示而扩大。
- 发布诊断不新增发布证据、不改变 release，也不复用旧诊断作为正式发布许可。
- 来源读取失败显示未知或部分结果，不显示“全部正常”。
- 页面跳转保留同一考试，并继续经过现有导航权限与未保存修改拦截。
- 停止、切账号、换范围后的迟到结果不进入新会话。
