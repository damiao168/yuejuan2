# 依赖安全基线与验证

本说明记录 2026-10-11 修复 CI 安全和隔离构建失败时的依赖约束。版本变化仍通过包管理器正常生成锁文件；不能只修改扫描规则或在锁文件中手写版本。

## Node 工作区

- Web Admin 和桌面端分别声明自己的 Testing Library 与 jsdom。Web Admin 的 Docker 构建只安装所选工作区，不能依赖学生端开发依赖恰好被提升到根目录。
- 三个客户端使用 Vitest 4.1.11，消除旧测试依赖链中的 tinypool 告警。跨主要版本更新需要检查 mock 回调类型及完整单测，不能删除断言来迁就升级。
- 根 `overrides.katex` 使 Markdown 数学渲染的传递依赖也使用已修复版本。`rehype-katex` 和 `micromark-extension-math` 的上游声明仍为 `^0.16.0`，仅升级客户端直接依赖会留下两个旧副本。[KaTeX 官方安全公告](https://github.com/advisories/GHSA-238p-pmpm-9mq7)列出的修复版本为 0.18.2；本轮最终解析为 0.18.10。
- 既有锁文件在普通更新后仍保留旧 KaTeX，不能以“已经加入 override”作为扫描通过的证据。本轮在隔离目录中暂时固定直接依赖的当前版本、正常生成新锁，再恢复原依赖范围并由 npm 正常同步，避免顺带升级 React、PDF.js、Tauri 等直接依赖。主工作区的依赖声明保持原范围；接受新锁前须通过 `npm ci`、完整单测、数学渲染、构建和浏览器回归验证。
- Lab 的 csv-parse 使用 7.0.3。Lab 评测需要完整单测、合成评测及开发门禁，结果不能被描述成真实模型评分准确率。

KaTeX override 跨越上游声明范围，因此不能只检查安装成功。维护时必须验证数学正文、公式错误处理及打印/渲染契约；上游允许已修复版本后，再评估移除 override。

## Go

`go.mod` 最低版本、GitHub Actions 和镜像构建统一使用 Go 1.26.9，`golang.org/x/net` 使用 0.60.0。只更新本地 Go 可执行文件会使 CI 和镜像继续使用旧标准库，不能视为完成漏洞修复。

`govulncheck ./...` 检查实际导入与调用路径。详细输出可能同时列出未导入的模块级告警；本轮 `golang.org/x/crypto/openpgp` 的无修复模块级告警没有实际导入或调用，不应与可达漏洞合并计数，也不能据此声称所有模块级告警为零。

## 交付检查

保留 CI 中的安全等级、覆盖率、架构大小与权限门禁。至少核对干净安装、根与 Lab 的 npm audit、Go 模块校验与漏洞检查、三个客户端单测与生产构建。最终以同一提交的 GitHub CI 结果确认隔离镜像和运行环境；本地宿主工作区构建不能替代真实镜像验证。
