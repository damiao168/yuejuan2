# 学生与阅卷教师账号

学校管理员新增学生时，同时填写姓名、学号、班级、初始密码和确认密码。名册、初始学籍、账号和学生本人权限在一个 PostgreSQL 事务内写入；任一步失败整笔回滚。CSV 继续只导入名册，导入后在学生列表逐人开通账号，不生成统一默认密码。

学生、教师和管理员共用一个登录页面，直接填写学校代码、账号和密码，不再选择教师端或学生端。服务端确认身份后，学生进入本人学生门户，其他身份进入已有工作区；学生门户失去会话时也回到统一入口，保留学校代码和本站学生考试返回路径。

学生使用学校代码、当前学号和密码登录。内部用户名由稳定学生 ID 生成，改学号不更换账号或历史成绩归属。修改学号、停用和恢复学生会同步账号并撤销旧会话；姓名修改同步账号显示名称。永久删除先撤销并停用关联账号，再解除学生外键，不保留可登录的孤立身份。

阅卷教师新增时填写登录账号、姓名、任教学科、初始密码和确认密码；手机号、工号可选。学校管理员邀请保留原流程。任教学科用于分配资格，实际数据访问仍按学校和分配的任务约束，不恢复班级管理绑定。

初始密码沿用现有策略，普通账号至少 8 个字符，并受协议字节上限限制。数据库只保存密码哈希，列表、审计和创建响应均不包含原密码。管理员编辑教师资料不重复校验管理员密码。

首次登录会话携带 `must_change_password`。前端只挂载改密页面；服务端认证中间件仅放行读取自身会话、修改密码和退出。修改密码必须验证初始密码、新密码不能与旧密码相同；哈希、标记、安全版本和会话/可信设备撤销一起提交。完成后用新密码重新登录。

密码与微信登录接受学校代码，教职工保留原租户代码入口；已绑定学生的密码登录使用学校代码和当前学号。代码必须定位唯一启用租户，再在该租户范围查询唯一账号；不能选择查询返回的第一条。登录前尚无会话，查询学生前须显式绑定刚定位的租户，否则学生表的 RLS 会隐藏合法账号；不能用跨租户维护上下文绕过隔离。

成功解析后的限流使用服务端规范租户、稳定账号 ID 和当前密码哈希的指纹，学校和租户别名共用额度，账号与来源 IP 的组合也使用相同身份。修改密码后自动进入新的凭据桶，旧失败记录按原 TTL 失效；新开通账号不沿用开通前未知学号的失败桶。同一来源下其他账号的失败记录不能由本次登录清除。

迁移 `000228` 只把既有明确的学生本人角色与同租户学生双向唯一关联；学校为空时可从该学生推导，混合职责、跨学校或多账号歧义不自动绑定，不更改任何历史密码。存在无法安全自动关联的旧账号时，开通请求返回冲突并提示管理员核对，不会替用户重置密码。

分离的内存名册和认证仓储不支持跨仓原子开通，HTTP 明确返回 503 且不写入部分数据；低层合成夹具和 CSV 名册导入仍可使用内存模式。完整账号生命周期依赖 PostgreSQL。

参考产品： [Google Classroom 学校账号](https://support.google.com/edu/classroom/answer/7582372?hl=en)由学校管理员创建与管理；[Microsoft Entra 初始密码](https://learn.microsoft.com/en-us/entra/fundamentals/users-reset-password-azure-portal)要求在下次登录时修改。本项目只采用管理员分配初始凭据和本人改密的基础流程。
