# 答题卡模板收录与复用：首批实施记录

日期：2026-10-16。对应[设计基线](answer-sheet-hybrid-processing-design.md)。本批保留工作区已有修改，新增学校库、模板配置入口的自动分流，以及真实 OpenCV/多模态候选分析。已完成本机 `8088` 站点的部署和真实账号页面验证；未部署到外部生产环境。

后续策略已按用户反馈调整为多模态主导，平台新增独立答题卡模型用途；当前行为以[本轮实施说明](answer-sheet-multimodal-first-implementation.md)为准。下面保留首批 `000190` 的实现和验收边界。

## 已接通的用户流程

在考试准备的“答题卡设置”中上传图片或 PDF 后，系统自动查询模板库。相同文件先用 SHA-256 匹配；未命中时，对本校且题号/题型兼容的候选执行整套页序、特征配准和静态结构验证。

- 唯一可靠匹配：建立或复用本场草稿，使用新考试的题目 ID；不再次逐题识别。
- 未匹配：自动创建草稿、逐页识别候选。保留现有文字层、本地框线和 Tesseract 结果，缺口调用后台 OpenCV + 学校文档模型。
- 候选冲突：先核对已有版本；不自动创建新模板。
- 检索不完整、内部视觉服务不可用或格式不支持：显示错误并保留重试，不能当作未知模板新建。

用户核对完整作答区后，点击“核对并收录模板库”，明确确认空白底图不含学生信息及布局适用于同版式。系统保存当前编辑、按刚保存的 revision 锁定，再收录不可变学校库快照。收录失败保留已保存/已锁定事实，重试不重复创建相同版本。

收录与本场启用分开：启用仍使用原有确认锁定、考试绑定及其独立版本游标。库命中后的本场实例是草稿，正常映射不要求教师选择已知/未知，但最终启用仍保留现有明确确认入口。

## 代码落点与实际约束

| 范围 | 实现 |
| --- | --- |
| 学校库 | `services/api-gateway/internal/paper/template_library_*.go`；同校查询、全题覆盖、唯一题号和题型映射；库不保存旧 `question_id`、答案、Rubric 或 OMR 校准 |
| 持久化 | 新迁移 `000190_answer_sheet_template_library.sql`；不可变快照、实例幂等关联、学校参考资产；同对象引用受数据库及文件删除入口保护 |
| 参考资产桥接 | 收录建立独立学校资产；实例化在事务中建立本场 `purpose=answer_sheet` 来源和模板，现有配准 worker 可继续读取 `exam_paper.file_asset_id` |
| 匹配 | `template_library_visual_client.go` 与 `grading_agent/template_matching.py`；至多 8 个兼容候选、每份 8 MiB、总 24 MiB；PNG/JPEG/PDF 按页序完整验证，不处理任意乱序分册 |
| 页面候选 | `template_page_analysis.go`；单页图片至多 1 MiB/400 万像素，推断前后核对权限、来源摘要、模板 revision 和题目签名；只返回候选，不保存或发布 |
| CV 与语义 | `grading_agent/answer_sheet_vision.py`、`template_analysis*.py`；真实框线检测/保守精修、题号/区域角色关联、跨供应商视觉消息；语义失败时保留未关联几何及原因 |
| 前端 | `features/answer-sheet-template/library/`、`editor/analyzeTemplatePage.ts`、`useRegionSuggestion.ts`、`AnswerSheetTemplatePage.tsx`；自动分流、逐页补缺、核对收录、源/账户作用域保护 |
| 锁定版本 | `LockTemplateAtRevision` 在同一内存写锁或 PostgreSQL 行锁下核对 revision；旧空请求仍兼容，新前端提交刚保存的 revision |
| 发布几何 | 新库专属校验拒绝题区之间、题区与身份区的有效面积重叠；仅触边和浮点误差不算冲突，不改变历史普通模板保存协议 |
| 契约 | 新增 5 条接口和旧锁定接口的正式 OpenAPI 定义，按脚本生成 SDK/路由覆盖，删除对应过时例外，schema 元数据同步为 `000190` |

OpenCV 匹配使用 ORB 特征、RANSAC 单应变换、内点分布、投影/覆盖及配准后的边缘结构共同验证。运行时提供 AKAZE 才启用该可选回退；缺少该能力不能让已经可靠的 ORB 结果报错。算法分数均为证据强度，不是正确率。

内部页面分析为 `POST /answer-sheet/analyze`，匹配为 `POST /answer-sheet/match`，都要求现有服务认证。学校文档模型未配置或不可用时，不使用评分模型冒充视觉模型；响应以 `semantic_status` 明确说明。支持 OpenAI 兼容和 DashScope 原生视觉消息，模型输出始终为 `review_required`。

| 失败调用费用完整归集/后台任务预算 | pending；返回已有供应商用量，不承诺每次外部超时费用已持久记录；没有恰好调用一次保证 |
| 无框、多样本提取、学生越界覆盖层 | pending；疑似冲突转核对，学生个体笔迹不能改写学校通用 ROI |

学校库中的每条记录是不可变版本，当前 `version_no=1`；编辑已锁定模板须克隆，再收录为新记录。完整模板族/版本管理和退役入口尚待后续实现，不能把同名记录当成已有版本谱系。

## 验证记录

- 前端类型检查和生产构建通过；模板模块及用户错误映射的 28 个测试文件、439 项测试通过，覆盖自动分流、旧作用域回执、库收录失败恢复、CAS 锁定和候选冲突。最终回归限制并行 worker，避免共享开发机内存不足影响验证。
- Go `internal/paper`、`internal/files`、`internal/server` 包测试通过；新增来源/版本/题号校验、视觉接口结果校验和收录门禁测试。
- 真实 PostgreSQL 在独立临时 schema 通过 3 项库事务集成测试：并发收录/实例化、失败回滚、不可变性、参考对象保护及发布/删除竞争。使用最小父表和正式新迁移，不等同于生产全库迁移验收。
- Go 客户端到实际 Python HTTP 服务的集成通过：实际 OpenCV 匹配和几何候选，不调用外部供应商。
- Python AI 服务全量通过 380 项测试及 269 项 subtests；视觉匹配新增的 7 项合成回归包含轻微旋转、同版相近候选、PDF 全页顺序、缺页、错误参考和摘要校验。
- 真实 Chromium 页面在合成来源和模拟业务 API 下完成自动候选→核对→保存/按版本锁定→收录；人工确认前按钮禁用，收录后显示库版本且本场尚未绑定。此检查验证交互，不当作真实模型/数据库端到端生产证明。
- OpenAPI breaking、生成 SDK/路由覆盖、授权矩阵和 schema 版本检查通过。定向 Python Ruff 与新增前端模块 lint 通过。
- 本机正式数据库已应用 `000190`，迁移摘要与源码一致；两张库表的强制租户 RLS、运行角色权限和两个保护触发器均已核对。部署前 PostgreSQL 归档已通过目录校验，未改写历史迁移。
- `8088` 真实验收账号可打开“答题卡设置”，看到学校模板库、上传和自动分流说明；库列表与模板列表接口返回 `200`，未登录访问库接口返回 `401`。实际页面控制台无错误，未使用 API 拦截。
- 部署后的 AI 容器经内部 TLS 和 Bearer 认证完成合成页分析，检出 18 个几何候选；同版来源匹配成功，无令牌请求返回 `401`。本项明确不调用外部供应商，不构成多模态模型准确率验收。

全仓架构门禁仍报告本批未修改的 `PlatformModelConfigPage.tsx` 超过页面行数上限；没有为通过门禁改动该无关工作区内容。

## 部署与试用

本机收尾已完成：API、AI 服务健康，学校库页面与真实接口可用。保留另一项并行工作发布的最新前端，其模板库功能已通过实际 HTTP 产物和浏览器核对；没有为统一标签覆盖这版页面。发布记录见[部署验收记录](../../reports/answer-sheet-hybrid-deployment-20261016.json)，页面截图位于 `output/playwright/template-library-live-deployed.png`。

实际部署配置原来仍指定 `000189` 和 Alpine AI 镜像，本次已同步为 `000190` 与 `python:3.11.15-slim-trixie`，并持久化新 API/AI 镜像选择。Docker 启动期间遇到残留通信端点故障，保留旧端点后恢复了引擎；未重置 Docker 数据。首次发布遇到并行前端更新，已回退应用镜像后重新发布，保留成功的新增迁移。

后续环境部署和试用：

1. 应用新增迁移 `000190`，运行 API 和重建后的 AI 镜像；同时核对实际 `.env` 的 schema 与 AI 基础镜像覆写值，不能只依赖 compose 默认。
2. 内部 AI URL/服务令牌继续使用现有受控配置；视觉语义模型跟随学校文档模型选择。外部模型未配置时仍可人工核对本地/CV 候选。
3. 在可修改的考试准备阶段上传答题卡，核对后收录；在同校另一考试准备中上传相同文件或清晰的同版扫描，检验自动匹配与新题号映射，再明确确认用于本场。
4. 初次试用保持人工核对，使用经授权的代表性样本验证题号、完整保留率、串题和复核耗时。库来源必须经过空白及无学生信息核对；系统保存该声明，不声称已自动完成脱敏。
