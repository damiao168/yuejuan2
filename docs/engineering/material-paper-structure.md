# 按考试资料建立题目结构

默认创建考试只保存名称、学科和预期满分，不生成预设小题。模板模式仍可明确选择预设结构；总分不用于补题、推断题目数量或平均分配分值。

## 采用流程

1. 上传完整试卷，识别结果保持为候选。答案、解析、评分标准按题号补充，答案文件单独出现的题号不增加正式题目。
2. 在考试资料或小题与分值打开结构预览，查看现有配置与资料识别的新增、调整、保留和移除项。
3. 管理员核对上传范围完整，勾选完整试卷确认后采用。部分页面不能用于判断试卷总题量；服务端无法仅靠模型识别证明资料完整。
4. 采用后到正式题目继续核对分值、答案、评分细则和答题卡区域。结构确认不等于准备就绪。

只有没有题干、选项、答案、解析、细则、题库来源和区域的多余占位题可以软删除。已有内容的多余题目或已生效评分配置发生变化时，预览阻止整批采用，要求单独核对。采用补齐空白内容，保留已有题干、选项、答案、解析和人工分值；识别答案存在冲突时不自动填入答案或解析。

大题内部的 `(1)`、`(2)` 继续保存在原题内容、答案和解析中，不按子问补出新整题。独立识别为父子行的候选暂不自动采用，必须先核对合并到对应大题；不能假装这些行就是额外的试卷整题。

## 分值和评分

`question.score_source` 区分 `human`、`preset`、`material`、`missing`。采用结构时只接受带明确资料分值来源或明确人工分值来源且确认的候选，保留现有人工分值；未知来源的历史数值和预设方案不能冒充资料分值。旧版整批保存曾把未逐项核对的分值也标为确认，不能单靠那个标记采用历史数字。存量预设题的现存正分值若与原分区不同，保守作为人工内容保留；分值一致时无法证明曾被单独确认。未知分值使用内部值 0，页面显示“分值待确认”，不能发布规则或通过准备就绪检查。零分不是允许评分的满分。

题干中的“取球得4分”“胜者得1分”是题目情境，不能作为考试小题分值。更换分值或题型后旧客观规则退役，历史记录保留；已有主观细则仍需检查与新满分的匹配。

## 状态、并发与恢复

`GET /api/v1/paper-imports/{id}/structure-preview` 返回差异、待确认分值、阻断原因和 `preview_hash`。

`POST /api/v1/paper-imports/{id}/adopt-structure` 接受 `expected_generation`、`preview_hash`、`complete_paper_confirmed=true`，需要 `exam:manage`。按租户读取当前导入和识别回执，只允许 draft/configured 考试；导入、当前识别回执、考试和题目按固定顺序锁定。旧代次或预览后人工编辑返回冲突，重新预览后重试；整批事务失败回滚。

采用记录 `structure_confirmed_generation/at/by`，并退役本考试的预设分区。追加或替换资料后代次变化，旧结构确认失效；确认事实参与就绪配置哈希。历史已应用导入沿用原流程，没有导入的手动考试仍可正常检查。采用后拒绝旧候选整批导入，避免覆盖正式题目的后续人工保存。

多余占位题软删除；替换资料重新出现相同题号时，仅可复用没有历史内容或评分规则的删除行。其他删除行返回冲突，不覆盖历史。部署迁移前备份数据库；迁移按正式 db-migrate 流程执行，不改写已应用迁移。
