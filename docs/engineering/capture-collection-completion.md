# 学生答卷导入结束与补传

## 完成判据

批次 `ready` 表示本批材料已处理完成，不代表全体学生齐卷。考试级概览由 `capture.CollectionSummary` 计算：以冻结的 `exam_candidate_snapshot` 为应收名册，缺考必须有明确的出勤记录；匿名、名册外材料和文件问题另列，不能混入学生人数。

每名非缺考学生须恰有一份有效且已匹配身份的答卷，页数与锁定模板一致，页号覆盖 `1..N`，分组完整，全部有效页面为 `ready`。缺卷、重复答卷、缺考却有答卷、分组或页号不完整、页面未就绪、答卷质量失败，以及未完成的文件/上传组/采集任务都会阻止结束。识别文字和评分是否生成不作为导入判据。

`GET /api/v1/exams/{examId}/capture-summary` 返回上述事实和独立导入修订号。`POST /api/v1/exams/{examId}/complete-collection` 在事务内重新计算全部事实；不能只相信前端按钮、批次缓存状态或人数相等。通过后统一封存有效批次，无有效材料的空批次取消，并记录完成时间、操作者和命令结果。

## 并发与重试

导入使用 `capture_collection` 独立台账。迁移触发器将名册、出勤、文件、页面和上传会话等相关写入纳入台账修订及关闭约束；任务提交结果时持锁，不在外部模型调用期间持锁。结束命令按考试、台账、批次顺序核对，遇到并发批次锁返回冲突，调用方刷新后重试。

结束请求携带 `revision` 和 `idempotency_key`。响应丢失后保留原请求和原键重试；服务端先恢复同键、同操作者、同载荷的原结果，再核对新请求的修订号。同键不同载荷返回冲突，不得修改原请求后复用旧键。

## 文件失败、整组替代和不计入

可先重试原文件；需要替代时先把新的一次完整选择全部上传、登记，再调用 `POST /api/v1/capture-files/{id}/exclude`，提交原因并以新组首个文件的 ID 作为 `replacement_file_id`。

一次文件选择是分组边界。排除其中一个文件会使该选择的全部文件及其答卷退出有效输入；原记录、处置原因和替代关联保留。关联页面、未评分切片和待运行任务一起处理，迟到的旧结果不能重新激活材料。已有评分或评分运行的材料拒绝在此处排除。

新组包含原组未损坏的同一图片时，退出旧组后释放对应新文件的 `duplicate` 标记，回到 `uploaded` 等待处理。登记或绑定成功不代表导入完成，新组仍须满足完整页号和页面就绪要求。不计入材料也不会自动消除学生缺卷。

排除响应丢失时，同一目标、操作者、原因和替代文件可以恢复；改变其中任何处置身份会返回冲突。作用域查询可读取已排除文件的考试归属，仅用于命令恢复授权，不能据此重新开放文件处理或下载。

## 阅卷与导入台账分离

考试进入 `grading` 不等于导入已结束。兼容原有分批阅卷流程时，尚未关闭的导入台账允许继续修复旧未封存批次；考试阶段本身不能伪造完成时间。

结束导入只将 `collecting` 推进为 `grading`，不会把已有的 `grading` 或 `reviewing` 回退。关闭后新增材料必须创建 `purpose=supplement` 的批次并填写原因；补传重开导入台账，保留考试阶段。补传仍须重新核对全场事实、处理重复答卷并执行结束命令，不能直接覆盖已评分来源。

## 000207 升级与回归

权威迁移为 [000207_capture_collection_completion.sql](../../services/api-gateway/migrations/000207_capture_collection_completion.sql)。它为已有考试建立未关闭的导入台账，不依据历史考试阶段补造齐卷结论，并加入命令回执、批次用途、文件排除信息及相关约束。应用层与该迁移一起交付；已应用迁移不直接改写。

使用隔离测试数据库设置 `EDUGRADE_E2E_DATABASE_URL`，在 `services/api-gateway` 下执行：

```text
go test ./internal/server -run '^TestCaptureCollectionCompletionWithPostgresTestDatabase$' -count=1 -timeout 5m
go vet ./internal/capture ./internal/server
```

闭环回归覆盖缺卷与缺考、错误 `ready` 缓存、同次排除重试、过期修订、并发锁冲突、结束同键恢复、迟到结果、补传保持阶段、重复材料处置以及同内容替代文件释放后的待处理状态。存量升级回归另使用 `TestPostgresMigrationUpgradeFrom000154`：先放入旧答卷和评分记录，再应用至最新迁移，核对原业务关系仍保留；不能以空库重放代替存量升级验证。
