# A01 参考图入队前预检

参考图模式在建立新的批量入队计划前，先核对冻结材料可读性，再读取当前数学 v2 评分实例的认证多图能力，最后按实际配置的供应方、部署、适配器、区域、模型、提示词及数学 wrapper 检查 image 准入。审批范围同时匹配冻结量规版本、学科、学段和题型。只有 text 审批或另一个可用部署，均不能放行当前参考图请求。历史单图和显式 `text_only` 路径不触发此检查。

预检只读取材料、能力与审批事实，不创建评分运行、发送许可或模型调用。A02 试改在标记运行及 AI 暴露前先执行材料预检；同题扩批只取精确试改批次的一份上下文检查共用冻结材料，随后由原有 Prepare 重新核验同题范围与版本。失败时不持久化新的入队计划，材料不可用、实例能力缺失及 image 审批不符分别返回列明的 422 错误，响应不包含底层数据库或供应商错误正文。

预检通过只代表检查时刻可用，不为排队期间提供持续授权。同一次入队请求对相同租户、题目、评估快照、材料绑定和实际策略复用检查结果，避免同题 1000 份扩批重复读取材料与能力；不跨 HTTP 请求缓存该结果。已有计划重放也不代表重新授予许可。实际发送前仍按该运行的准确模型、提示词、量规与冻结材料身份重新检查审批，并由共享持久许可决定是否允许消费；审批过期、撤回、部署停用或材料授权变化后，后续消费可能被拒绝。能力响应不跨实例长期缓存，实际请求仍由接收实例校验 wrapper。

相关入口：`subjective/math_grading.go` 的 `prepareMathEvidence`、`subjective/material_capabilities.go` 的 `ReferenceMaterialCapability`，以及 `server/reference_material_admission.go` 中预检与消费共用的 image 准入函数。此检查不证明模型理解图片或评分正确，也不启用新的 API 路由。
