# 成绩数据与质量样本维护

## 确认、发布和总分

旧版确认和公开入口在考试锁内执行完整性及总分一致性检查。当前终分之和与总分不一致时返回 `score_integrity_mismatch`，管理员须重新汇总待确认成绩后再确认。不能把汇总阶段的质量提示当成已经确认，也不能跳过未到卷、缺页或未完成阅卷的检查。

## 租户表与证据文件

迁移 `000221` 为正式题分、总分、成绩发布、题目申诉、考生快照、复核与仲裁任务、答案候选和 AI 评分运行补齐强制 RLS。身份认证表须在确定租户前读取，不能不加区分地套用业务表策略。

该迁移之后新增带 `tenant_id` 的表，必须在同一迁移中显式启用、强制 RLS 并定义策略。`internal/db/audit_grade_rls_test.go` 随 Go 测试检查这些声明；登录前读取等例外须在门禁白名单中写明原因。动态 SQL 创建的表也须单独验证运行角色，文本门禁不能替代 PostgreSQL 验证。

通用文件删除只接受未绑定考试或答卷的 `generic` 文件，并盘点数据库中指向相同存储对象的所有外键引用。已关联的答卷原图、规范化图、裁切图、采集文件和正式材料由证据留存流程管理。当前引用表安装了活跃文件校验触发器；新增文件引用表时也须安装该触发器，防止在文件进入待删除状态后追加引用。删除与新增引用先共用对象键 advisory lock，再分别持有文件排他锁和 KEY SHARE；对象键锁也覆盖多个资产共享同一对象的情况，不能把检查和状态变更拆开。

`file_reconciliation_finding` 是维护台账，需要记录未上传、缺失、隔离或待删的资产。它保留资产外键和租户一致性校验，不要求资产仍活跃，也不把历史巡检记录当作业务防删引用。新增例外必须逐表说明维护用途，不能对未知引用表统一放行。

## 校准与盲投分池

标准图像的用途按租户和内容 SHA-256 首次登记后固定。新提名图片以哈希首字节奇偶自动划入校准或盲投池；现有标准卷的新版本沿用该卷用途。已经登记的图片重复提名或换题时保持原用途；新版本若引用的图片属于另一池，拒绝保存。用途只在服务端使用，不进入普通阅卷任务响应。

迁移前的图片可能已经通过校准公开过参考分，因此全部留在校准池。旧盲投策略暂停、在途旧盲投任务过期、旧校准资格撤销；管理员补充新的盲投图像并重新确认策略，阅卷员重新校准。旧图不会因为升级被重新划作盲卷。校准池不足时明确返回 `calibration_gold_set_incomplete`；盲投池为空时无法启用策略。

校准每次从本池随机抽取策略指定的最少样本数量，资格指纹仍绑定整池版本。逐题提交只返回本人已提交内容；参考分、细则期望值、逐题误差和匹配结果只在服务端保存。整场结束后才返回汇总一致性指标。失败后同一题和阅卷者需等待 24 小时再考，创建和完成会话共用事务锁，避免并发绕过。

## 接口与客户端一起升级

模型配置的普通编辑和密钥轮换都必须发送打开表单时取得的 `expected_updated_at`，缺失版本返回请求错误、旧版本返回冲突。旧客户端不能再依靠无版本覆盖写入；先重新读取配置，再由用户重做修改。

校准响应不再包含 `reference_score`、`absolute_error`、`exact_match`、`within_one`、`severe_disagreement`、`criterion_correct`、`criterion_count`、`criterion_differences`。后台显示本人提交与整场汇总结果。后端、OpenAPI 和生成 SDK 已同步调整，发布时需要一并更新客户端。兼容性变更审查记录保存在本轮修复报告中，不通过手改生成文件保留这些泄露字段。
