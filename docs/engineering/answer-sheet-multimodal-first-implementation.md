# 答题卡多模态主导与平台用途分配

2026-10-16，本轮在[首批学校模板库实现](answer-sheet-hybrid-implementation.md)上修正识别策略。用户反馈传统识别效果差，因此实际未知模板入口改为逐页多模态理解，OpenCV 只提供几何提示与精修。管理员直接配置并分配模型，不增加测试图片检测或额外视觉验证门槛。

## 实际识别链路

1. 上传后先匹配学校模板库，可靠命中的正式布局继续复用。
2. 未知模板或教师主动识别草稿时，每页渲染后直接请求后台，不再根据本地 OCR 看似已匹配就跳过模型，也不等待本地 Tesseract。
3. 多模态看整页，理解题号、身份区、作答区；无 OpenCV 框也会请求模型，模型可以发现漏框、忽略误框。
4. OpenCV 在有可靠印刷边界时精修；模型新框保留来源和复核原因。同题多框、越界、未知题号或冲突不自动关联。
5. 模型失败时明确显示安全错误分类，并保留未关联几何候选；不会改用 OCR 猜测题号并宣称识别成功。
6. 页面持续显示本次实际完成分析的模型名。候选仍须保存、核对、锁定后才能收录或用于本场。

现有人工框不会被自动覆盖，包括已经手工修正过的历史 OCR 框。需要替换这些区域时，先点击“清空旧题区”并确认，再重新识别。清空只修改本地草稿的各页题区及未关联候选，保留定位区、身份区和页面来源；不会自动保存或发起模型分析。来源、模板、编辑器版本、权限或忙状态切换后，旧确认失效。系统不根据历史 `suggestion_source` 猜测一个框是否已经被教师调整。未提供后台分析器的旧兼容调用仍保留原有本地分析路径，实际答题卡设置页始终接入后台分析器。

## 平台管理员配置

入口为“模型管理 → 配置学校 → 学校模型库 → 应用用途 → 答题卡识别”。可选用启用且已配置凭据的本校模型，也可取消分配。多模态模型的供应商、地址、模型名及密钥沿用已有学校模型配置；没有新增环境变量秘密或在教师页面输入密钥。

这个用途独立于日常对话、试卷解析和阅卷角色。管理员可以指定同一个已配置模型，也可以单独配置其他模型；更换聊天默认项不会自动改变答题卡模型。无需额外测试图片、`vision` 探测模式或视觉证据字段，模型是否能处理实际页面在真实识别响应中校验。

新迁移 `000191_answer_sheet_model_selection.sql` 只新增学校用途表、强制租户 RLS 与权限，不改变旧模型凭据或现有默认用途。新表存放独立 revision，首次保存使用 `absent`；并发修改返回冲突。已被选择的模型不能直接删除，须先取消或改配。

## 接线与协议

- `PUT /api/v1/platform/answer-sheet-model-selection` 保存 `tenant_id/expected_revision/mode/model_config_id`；mode 为 `model/unconfigured`。
- 现有 `GET /api/v1/platform/model-applications` 增加 `answer_sheet_selection`，旧文档解析和评分字段保留。
- 教师分析使用独立的 `TemplateVisionResolver`。未配置、停用或凭据不可用时返回 `template_vision_model_required`，不借用聊天/评分/文本解析模型。
- 内部 `answer-sheet-analysis-v1` 保持外部响应形状；整页发现的新框由服务端生成稳定 `model-*` 编号，始终 `review_required`。
- OpenAI 兼容图像消息使用 `detail=high`；DashScope 继续使用原生视觉消息。模板专用输出预算至少 8192 tokens，不增加分析轮数，不改变评分模型参数；截断或失败保留已知用量。
- 前端持久候选来源使用 `multimodal_layout`，不再将模型结果标成 `ocr_layout`。旧结果来源不回填。

## 验证与限制

已覆盖本地识别看似完美也调用模型、模型纠正本地错误、无框整页发现、跨页/人工区域保留、取消与换账户、模型失败分类、真实模型名显示、平台独立选择/取消及 CAS。Python 测试使用受控模型替身，不能当作供应商真实识别准确率证据。

真实 PostgreSQL 测试在唯一临时 schema 中正式执行 `000191`，验证 SQL 仓储、并发 CAS、实际运行角色的租户 RLS、跨校复合外键、停用和引用防删；未改写共享学校业务行。

真实学校模型配置由管理员选择，本轮不自动启用停用模型、不替换聊天默认项、不发起被用户明确取消的测试图片请求。正式学校扫描件的准确率仍需真实识别结果核对。旧的一题一个 ROI 协议、刷新恢复未保存候选和其他后续范围仍见首批实施记录。

## 本机交付验收

本轮三个应用镜像已更新到 `answer-sheet-multimodal-20261016-230144`，本机 `http://127.0.0.1:8088/` 的实际静态资源包含“多模态识别区域”和学校模板库入口，数据库已应用 `000191`。三服务健康、就绪检查通过，匿名学校模板库请求返回 401。

使用真实平台管理员会话打开学校模型库及答题卡用途抽屉：当前学校用途读取为 `unconfigured`，可直接选择已有启用模型并保存，没有额外视觉检测控件；页面无控制台错误。本轮只打开配置并取消，未替学校分配模型，未调用外部图像接口。

前端相关回归基线 34 文件 567 测试通过；收尾的清空按钮及工具栏定向 3 文件 96 测试通过，其中新增清空边界 13 例。最终冻结源码的 TypeScript 检查与生产构建通过，构建后源码差异为空。Python 全套 396 测试及 269 个子测试通过；Go paper、modelgovernance、server 包与新选择器的真实 PostgreSQL 定向测试通过；契约、权限矩阵及 schema 版本检查通过。这些验证说明接线和失败边界成立，不表示真实供应商的答题卡识别准确率。

## 实际扫描件反馈后的修正

实际两页扫描件暴露了两个独立问题。第一页的浏览器框线检测对象还包含 `confidence`，适配器曾把整个对象作为 `bbox` 序列化。后台严格解码只接受 `x/y/width/height`，因此在调用模型前返回 400；通用错误翻译又把它显示为表单必填项错误。适配器现明确选择四个坐标字段，并使用答题卡分析专用提示。后端继续拒绝未知字段，测试保护错误请求不调用模型、合法四字段可调用模型。

第二页在未保存任何题区的情况下，实际兼容接口返回了题号 1～19、`x=0.05/width=0.9/height=0.05/y=0.05*n` 的均分横条。它们不符合页面上的三列答题区，却通过了原有格式校验。这说明“HTTP 成功、JSON 合法”不能等同于版面识别正确，也不能仅凭配置名称宣称模型已经理解图片。

当前页提示词明确 `question_labels` 是整场考试题号白名单，不是本页应补齐的清单。模型须只返回本页实际可见的题号和答题空间。新质量规则只标记同时满足以下特征的结果：至少六个宽横条、覆盖九成以上整场题号、左右位置及高度几乎一致、从页首附近连续覆盖至少八成页面，且没有本次 OpenCV 的完整印刷框支持。它是异常复核规则，不是对所有等高版面的错误判定；真实印刷行表有完整框线支持时豁免。豁免重新计算几何证据，不能相信模型自己填写的 `PRINTED_FRAME_VERIFIED`。

命中后保留后台候选与 `SUSPECTED_SYNTHETIC_PAGE_PARTITION`，撤销自动题号关联；前端忽略这批模型伪框并明确提示，不继续画成可用候选或计入已配置题目。已有人工草稿不按外观自动删除，教师可使用“清空旧题区”处理自己确认错误的旧结果。模型标注改为“已完成页使用”，部分页失败不代表所有页都完成。提示词与算法版本升至 v3，外部响应协议仍为 v1。

本次配置实际通过第三方兼容入口转发。没有修改学校模型、启用其他配置或增加测试图片检测；缺少该入口的图片透传及实际模型能力证据时，不能将这次伪框简单归因为所有同名模型不支持图像。异常拦截只防止错误自动关联，不能代替一个能正确理解实际扫描件的模型。

更新提示后的第二页实际重试仍返回了题号 1～4 的宽横框，而页面实际为 17～19 题三列。这次四框不符合上述“覆盖整场清单”的特定保护条件，不能将该保护说明成所有无依据坐标的识别器。本轮确认了请求格式故障已解决、十九横条样例已被拦截，尚未证明当前第三方路由能可靠识别该扫描件；继续验证正确框选需要管理员确认可用的图像模型路由。实际扫描件验证只发了已有页面，未发独立测试图片，未保存或锁定教师的模板草稿。

## 模型切换后的错误诊断

2026-10-17，管理员已将同一答题卡用途配置的实际模型改为 `glm-5.3-flash`，独立分配无需重绑。首次实际两页识别均返回 `model_request_rejected`，没有把任何结果当成成功关联。当前官方文档说明该模型支持 `image_url` 和 Base64 图像输入，不能仅凭这次第三方兼容接口拒绝就判断模型本身不支持图像。

供应商非成功响应原先只保留通用错误类别，难以区分模型路由、参数和权限问题。现在仅答题卡的 `semantic_error` 可额外带 `upstream_http_status` 和固定白名单内的 `upstream_error_code`；不改变其他操作的通用错误协议，不透传供应商原文、任意错误码或请求内容。错误正文读取最多 16 KiB 加一个超限判断字节；超限、读取失败或 JSON 不合法时仍保留已知 HTTP 状态及原有错误分类。前端只翻译白名单类别，并优先显示模型失败，避免重叠提示掩盖供应商拒绝。

本轮不自动启用其他配置、改绑模型或添加测试图片门槛。错误诊断只用于真实上传页面的失败定位，不能证明路由具有图像理解能力。供应商错误处理与模板分析定向 104 项测试、7 个子测试通过；前端适配器 24 项测试通过。真实页面结果另见本次验证报告。

诊断版上线后的真实两页复测均为供应商 HTTP 400，模型标识为 `glm-5.3-flash`，未取得安全白名单内的进一步错误类别。新页面分别显示两页图像请求被拒绝，无“已完成页使用”成功标识；保存布局仍为零题区，未保存或锁定本次候选。当前中转接口拒绝原因尚未定位到具体参数，需要该路由的图像调用说明，不能把失败归因为框线算法或宣称识别已经恢复。运行镜像、测试与安全坐标摘要见 `reports/answer-sheet-model-verification-20261017.json`。

随后管理员改配到官方 `api.deepseek.com` 的 `deepseek-flash`。按用户要求重试原两页，两页均返回语义完成；第二页返回 17、18、19 题的三个纵向区域，预览位置与三列印刷区一致，不再出现十九横条。第一页仍有重叠及重复题号，只有 6/19 题被自动关联，不能据此确认整份模板准确。验证没有保存、锁定或发布模板，也没有更改学校配置。此次实际响应及预览证据见 `reports/answer-sheet-deepseek-retry-20261017.json`。
