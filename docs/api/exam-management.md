# 整场考试管理

考试列表按整场考试管理。已有 `exam_session` 承接多科考试，学科 `exam` ID 继续用于试卷、答卷、阅卷和正式成绩；没有父级的历史考试按单科整场展示，不改写原 ID。

## 查询与操作范围

- `GET /api/v1/exam-management`：按整场分页，支持 `school_id`、`grade_id`、`search`、`exam_type`、`status`、`archive`、`limit`、`cursor`。
- `GET /api/v1/exam-management/{kind}/{id}`：读取最新整场详情；`kind` 为 `session` 或 `standalone`。
- `PATCH /api/v1/exam-management/{kind}/{id}`：修改整场名称、类型或默认参考班级。
- `GET /api/v1/exam-management/{kind}/{id}/archive-check`：返回 `check.allowed` 与 `check.blockers`。
- `POST /api/v1/exam-management/{kind}/{id}/archive`：归档整场。
- `POST /api/v1/exam-management/{kind}/{id}/restore`：恢复本功能建立的归档。
- `GET /api/v1/exam-management/commands/{commandID}`：按当前租户和操作人恢复归档或恢复命令，返回 `{ command: { command_id, status, exam? } }`。`status` 为 `succeeded` 或 `not_accepted`。

列表响应为 `{ exams, next_cursor?, has_more }`，详情和成功写入响应为 `{ exam }`。单场包含完整的授权学科、`scope_complete`、`can_manage`、`can_edit`、`can_archive`、`can_restore`；不允许客户端从当前分页或状态筛选推算整场范围。可读取部分学科的身份不能执行整场写入。

`class_ids` 是授权学科参考班级的去重并集。`default_class_ids` 和 `inherited_subject_ids` 表示默认班级及受其更新影响的学科；独立选班的学科保留自己的范围。学校、年级和单科满分等不属于该 PATCH 的修改字段。

## 版本与失败处理

整场编辑携带 `expected_revision`；场次考试同时携带完整的 `expected_subject_revisions`，只有一科的场次也不能省略。父级版本不会自动代表所有学科配置版本。任一版本或学科集合改变、权限不足或受影响名册冻结时拒绝整次操作，不留下部分学科变更。

归档、恢复携带 `command_id`、`expected_revision` 及学科版本，并使用同一 `Idempotency-Key`。相同命令与相同输入重放原结果；修改输入不能复用同一命令。超时后先恢复原命令结果，不能直接生成新命令重复提交。

界面在提交前将原命令和版本按租户、操作人、考试和动作保存到本地。重新打开操作时先恢复命令；只有 `not_accepted` 才重放原输入。成功回执是历史结果，界面重新查询当前考试，避免旧归档回执覆盖后来完成的恢复。恢复回执和重放仍检查当前整场权限。

归档前检查只提供当前提示，归档事务仍重新读取任务、发布和申诉事实。客户端不得将先前 `allowed=true` 当作提交授权。读取来源异常时拒绝归档，不能以空列表代表任务已完成。

## 汇总进度

`progress` 返回 `status`、`label`、`total_count`、`ready_count`、`published_count`、各阶段 `counts` 和 `facts_available`。

- 准备完成数依据有效准备确认。
- 发布数依据当前正式发布记录，单科状态字符串 `published` 不能替代发布事实。
- 多个阶段并存显示实际阶段分布，不统一解释为“配置进行中”。
- 读取失败或未知状态不能显示为 0%、100% 或已完成。
- 状态筛选只选择整场，不改变详情、编辑或归档的目标。

## 归档与只读边界

迁移 `000183_exam_management_archive.sql` 将归档信息与各科业务状态分开保存。归档不删除资料、不改写各科流程阶段、不撤销正式发布、不改变已有成绩访问权限。恢复只撤销归档，原有发布和冻结限制继续生效。

允许归档的范围：整场未开展且没有答卷或业务任务；或全部学科已有正式发布、任务已结束、申诉窗口关闭且申诉已处理。存在未完成事项或无法核实必要事实时返回具体阻断原因。历史 `status=archived` 保持只读，缺少可靠原阶段时不自动恢复。

HTTP 资源边界在权限检查之后拒绝已归档对象的写操作。数据库约束处理直接写入、worker 写回与并发归档，不能仅凭界面禁用保证只读。GET 等读取仍可使用原权限访问。归档、恢复的审计与命令回执同事务提交；编辑沿用现有 HTTP 审计机制。

旧 `POST /api/v1/exams/{id}/archive` 和普通状态接口中的 `status=archived` 返回 `409 exam_management_archive_required`，引导使用整场归档。其他合法阶段推进继续使用原接口。保留历史归档的读取兼容，不再从这些入口生成丢失原阶段的归档。

后台处理投影在同一业务锁下读取归档事实。归档后保留原有状态和异常记录，仍确认当前租约领取的消费版本；后来新增的版本不能被旧任务一并确认。读模型游标和纯投影表不属于考试业务修改，不能因归档让后台无限重试。

运行任务没有声明式外键的来源由迁移中的白名单追溯。新增任务来源或考试业务表时，必须同步只读约束和归档条件集成测试。

## 前端入口

考试行提供“考试工作区”“查看考试详情”“编辑考试”“归档考试”，归档列表提供“恢复考试”。去掉手动“开始配置”和默认单科状态推进。整场工作区先展示授权学科，由用户明确选择后进入现有单科路由；访问工作区不修改业务状态。单科工作区通过 `exam_session_id` 返回整场总览，历史单科返回自身总览。

单科工作区的 `read_only` 独立于 `exam_status`。已归档或无法确认归档事实时禁用业务修改；读取、已发布成绩和已有报告继续按原权限访问。来源异常时提示“状态暂无法确认”，不能断言考试已经归档。

## 验证

整场 PostgreSQL 验收测试在隔离数据库中应用全部迁移，覆盖 53 场跨页查询、公共编辑与独立班级范围、版本冲突、归档与恢复、开放申诉和运行任务阻断，以及归档前后当前正式成绩读取一致。另一个真实 PostgreSQL 测试验证重复命令、恢复后的迟到归档回执、权限收回、等待归档提交的直接写入被拒绝，以及后台投影只确认领取版本。

前端验证多科操作对象不受筛选影响，详情覆盖全部学科，学科配置入口明确显示目标；构建和契约生成检查同时通过。浏览器展示用测试夹具，真实数据库业务验收另行完成，避免把模拟页面当作现有环境已经部署。
