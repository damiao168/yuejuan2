## 1. 结论

问题同时发生在资料解析、蓝图对账、配置应用、评分规则生成和页面呈现五个环节。仅缩短表单或重新上传资料不能解决。

建议把当前体验改成“上传资料 → 自动生成题目与评分草稿 → 在一个工作台核对差异 → 确认评分版本 → 开始批阅”。题干、选项、参考答案、详细解析、评分依据应在同一题目上下文里展示；答题卡切块继续留在答题卡模板模块。

必须区分两种自动化：从资料中**提取既有事实**，与根据解析**生成建议评分标准**。前者不应编造；后者可以满足用户期待，但必须标明是建议、记录生成依据，并经确认后成为正式阅卷依据。

## 3. 代码确认的问题与原因

### 3.1 分值提取缺乏语境和分值来源

`ai-services/grading_agent/paper_compact/schema.py` 的 `_SCORE` 允许匹配任意“数字 + 分”；`anchors.py` 对整个题目原文执行首次匹配。概率、比赛、积分制题目天然包含这样的文字。

修复要求：

1. 优先识别题号附近的“本小题满分”“本题共”“（N分）”等评分标记。
2. 单独提取大题标题里的题数、每题分值和总分，按明确题号范围分配。
3. “胜者得分”“取球得分”“积分”“净胜”属于情境数值，不进入试题分值字段。
4. 每个分值保存独立来源：资料直接标注、章节统一规则、原蓝图建议、人工设置。未知值使用 `null`，界面显示“待确认”，不要把缺失显示为 0 分。
5. 当前第 8/18 题已有确认标记也不能作为准确性证明；重新核对分值时应明确提示其来源异常。

只有确切同题、同题型、无来源冲突时，才可以把已有蓝图分值预填为建议。不能按“常见高考分值”或为了凑足 150 分反推本卷分值。

### 3.2 已有题目导入不会更新分值和题型

`paper_import_reconcile.go` 把原有蓝图作为分值与题型的权威值；差异被标为冲突。`paper_import_postgres.go` 的已有题目更新 SQL 只更新试卷关联、题干、知识点和来源，没有更新 `score`、`question_type`。

即使资料正确识别出分值，用户期望的“根据资料自动补齐小题分数”也不能由现有应用操作完成。

建议新增字段级差异方案，而不是悄悄修改权威顺序：

- 对空题蓝图，自动提出资料配置方案。
- 对已有人工内容，显示“当前值 → 资料值 → 来源”；提供采用资料、保留当前、人工修改。
- 保存 `expected_revision`、解析 generation、来源 revision、选择策略，防止旧结果覆盖新编辑。
- 对 21→19 的变化，展示保留空题、补充资料、采用资料结构三种处理，不自动删除。
- 在草稿状态允许调整；已有答题卡布局需要提示重新绑定；开始正式阅卷后走新版本和重评流程。

### 3.3 资料提取器没有评分草稿生成能力

当前模型提示明确禁止根据题目、答案或解析生成缺失的评分标准。这条约束适合忠实提取，却无法满足“详细解题步骤自动变成评分点”的需求。

而确定性锚点解析路径直接返回空的 `rubric_candidates`。快速结构化不应意味着后续评分处理被跳过；若输入明确含评分文字，也应继续交给评分提取阶段。并行复核已做最小输入复现：包含“答案、解析、移项正确得2分、求得x=2得2分”的4分题命中快速路径，得到解析1份、评分标准0份。原文评分标准漏提取属于P0缺陷，独立于新增草稿生成能力。

建议保留原提取约束，增加独立的评分草稿阶段：

| 资料内容 | 系统行为 | 页面标记 |
| --- | --- | --- |
| 有明确采分点和分值 | 忠实提取并校验合计 | 资料评分标准 |
| 有详细解法，只有题目总分 | 生成采分点与建议分配 | AI 建议，待确认 |
| 有详细解法，没有可靠题目总分 | 生成采分点描述；分值待定 | 缺少满分 |
| 只有最终答案，没有可验证解法 | 提示补充解析；可另行生成参考解法草稿 | 参考解法待核对 |
| 解析内部矛盾或子问缺失 | 标记问题并定位原文 | 需要处理 |

题目、答案、解析不完整仍应可保存；它们不能被标记为“可开始 AI 批阅”。

### 3.4 客观题默认规则没有形成完整闭环

当前自动客观题 rubric 只有在满分大于 0 且标准答案非空时生成。此次大量分值缺失使默认点评分无法生成。

填空题被特例化：不会生成 rubric，归一化时还会主动清掉 rubric。该设计本身可以成立，但界面必须展示实际答案和固定判分规则，而不能显示“无需配置”后把关键依据隐藏。

资料应用不会创建 `scoring_rule`；页面要求用户逐题另行保存和发布规则，增加重复劳动。

建议统一提供一个“评分标准”界面，内部按题型执行不同引擎：

| 题型 | 默认生成的评分配置 | 需展示的例外 |
| --- | --- | --- |
| 单选/判断 | 正确答案 + 全对得满分，否则 0 分 | 答卷识别不确定时人工确认 |
| 多选 | 正确选项集合 + 全对/少选/错选规则 | 少选给多少分必须来自资料或明确选择 |
| 填空 | 每空答案、每空分值、等价形式、必要容差 | 多空是否按顺序；单位；精确值与近似值 |
| 数学解答 | 子问 → 采分点 → 分值与证据要求 | 替代解法、步骤依赖、错误延续、部分分 |

数学填空不能采用通用文本清洗后直接等价。`(0,1)`、`[0,1]`，以及 `x`、`X`，可能表达不同数学对象；忽略标点和大小写不能作为数学默认规则。有依据时支持 `1/2` 与 `0.5` 的数值等价，但精确表达、区间端点、符号和题目要求必须保留。

按题型生成配置草稿，确认后一次发布答案与规则的组合版本。客观题不需要教师手工重写一句“回答正确得满分”的 rubric。

### 3.5 题目结构、参考答案与 AI 上下文有断点

资料候选包含选项和父子题号，但导入草稿没有选项及父子结构字段。资料审阅页面从候选回查选项，所以审阅时能显示；正式应用只写题干，无法完整持久化候选的选择题选项。当前 19 个题目候选共识别 44 个选项。

必须把选项、材料、配图引用、子问和答案保存到正式题目内容中；不要靠回查某次导入任务才能重建题目。

当前数学 `grading-agent-v2` 请求包含题干、rubric、学生答案图片与数学证据，但没有独立的标准答案和教师详细解析字段；builder 将 `equivalent_answers`、`scoring_notes` 固定为 `[]`。资料里的详细解析不会因为上传成功就自动成为 AI 批阅上下文。

建议从同一冻结题目版本生成阅卷上下文，至少包含：题目完整内容、所有子问参考答案、教师详细解析或经确认的精简解法、正式评分点、学生题块图片/OCR/步骤与公式证据。增加字段必须同时升级 Go/Python 契约和测试；不能往现有严格 schema 里随意塞字段。

### 3.6 界面状态和保存方式容易误导

`PaperRubricPage.tsx` 当前行为包括：

- 标准答案统计以是否有 `answer_key` 对象为依据，未检查答案有效性。
- 填空题列表直接显示成功态“按答案评分”，不检查答案是否为空。
- 除填空题之外的选择题也进入人工 rubric 编辑器。
- 题目、评分细则、客观规则分别保存；用户难判断当前题是否已完成。
- `useQuestionEditor` 每次保存都发送答案和坐标；缺失坐标默认 0，保存题干也会创建答案版本。
- 数学公式主要放在原始文本框里，正式题目编辑区没有完整的参考解析阅读体验。

建议以字段实际有效性生成状态：待补分值、答案缺失、评分待确认、已确认、可批阅。分别统计识别完成、内容已保存、评分已确认，避免一个绿色标签覆盖所有状态。

坐标字段由答题卡模块管理。保存题目内容时不发送无关坐标，也不因仅修改题干而无条件创建答案版本。结构化答案必须结构化编辑，不能通过 `String()` 把数组/对象降成文本。

## 4. 推荐页面设计

把“资料校对”和“正式题目配置”合并为一套题目工作台。上传、处理进度和资料历史保留在资料页；点击识别结果进入工作台，直接看到已识别内容及其状态。

采用“窄题目导航 + 宽当前题详情”两栏，不再永久摆放题干栏和另一条详情栏。来源文件按需打开抽屉。

```text
考试：1 · 数学       资料识别 19 / 蓝图 21       [处理结构差异]
────────────────────────────────────────────────────────────────
题目导航                    当前题：15  解答题   满分：待确认
─────────────────           [评分标准] [题目与参考解答] [来源]
全部 / 待处理
单选 1–8                    题干摘要（可展开，公式可阅读）
多选 9–11                   子问（1）
填空 12–14                  采分点 / 分值 / 来源 / 状态
解答 15–19                  …
20、21 待核对               子问（2）
                            …
                            合计与题目满分对照
────────────────────────────────────────────────────────────────
                            [上一题] [保存草稿] [确认并下一题]
```

具体交互：

1. 题目列表只展示题号、题型、分值和真实缺失状态；题目多时列表独立滚动。
2. 详情默认展示评分标准，旁边有完整题目与参考解析页签；同一题内切换不丢编辑内容。
3. 顶部题号/满分、底部保存与下一题操作固定可见；长内容在详情区内滚动，评分点长表格保留列头。
4. 参考解析按子问展开；LaTeX、表格和配图正确渲染；“编辑原文”只在需要时出现。
5. 来源抽屉打开对应文件并定位到页码、文字块或文本范围，而不是只打开整份文件。
6. 切题前保存草稿或明确提示未保存内容；数据刷新不能覆盖正在编辑的草稿。确认和发布是独立动作，不把保存草稿当成审批。
7. 批量操作采用一个变更汇总：如“补齐 14 道客观题答案与规则，5 道解答题评分待确认”，每个冲突可展开。
8. 1366×768 和 1440×900 下，当前题分值、状态、保存操作应无需滚动即可找到。窄屏改为题目选择器加单栏详情；不把两条长栏直接堆成更长页面。

| 当前字段 | 建议处理 |
| --- | --- |
| 关联试卷版本 | 从逐题主表单移除；系统记录来源和配置版本。只有实际 A/B 卷业务才显示试卷选择 |
| 知识点 | 移到可选的教学分析信息；不作为评分准备前置条件 |

## 5. 数学解答题的评分草稿生成

生成器每题运行一次，依据当前题干、所有子问、可靠题目满分、教师答案和详细解法生成结构化评分草稿；正式阅卷复用已确认版本。

每个采分点应描述可判断的数学事实，例如“正确求得回归斜率 0.5”，而不是“步骤正确”“理解题意”。每个点区分方法、计算、结论、证明或单位条件；关联子问和资料依据。

生成后做以下校验：

- 同一子问的分值合计等于子问满分，题目子问合计等于题目满分；不为凑分发明新评分点。
- 划线排版的每一行不等于一个评分点；一个数学动作可能跨多行，多个评分动作也可能在一行。
- 方法分与结果分分开，避免一个算术错误把后续合理方法全部判错。
- 替代正确解法按同一数学目标映射；不得要求学生按参考解法相同行序或相同公式书写。
- 结果是否依赖前面的正确方法、是否允许错误延续，必须是明确规则。
- 同一数学事实不重复给分；替代路径不能相加超过题目满分。
- 对无法核验的图形、证明、识别不清的公式保留不确定状态，交给教师处理。

上述方法分、结果分和错误延续是可参考的建模方式，具体分配必须遵循本校本卷要求，不能直接套用海外考试规则。

## 6. 给 AI 的评分点格式与版本边界

### 6.1 当前契约可接收的 rubric

仓库现有 `grading-agent-v2` rubric 支持：`rubric_id`、`rubric_version`、`question_type`、`max_score`、`allow_partial_total`、`points`、`deductions`、`equivalent_answers`、`examples`、`scoring_notes`。每个 point 为：

```json
{
  "id": "q15-part1-regression-slope",
  "description": "正确使用最小二乘法求得回归斜率 0.5。",
  "score": 2,
  "required": true,
  "aliases": [],
  "evidence_required": true,
  "match_policy": "semantic"
}
```

配套文件 `examples/q15-rubric-current-contract.json` 是按当前契约编写的六点评分示例。示例借用第 15 题解析，暂用原蓝图 11 分演示字段；其 2/2/2/2/1.5/1.5 分配是建议示例，并非本卷官方标准，不能直接应用。

当前 builder 会重建这些字段，固定清空 aliases、等价答案和评分说明；仅有一个合法 JSON 文件并不意味着这些信息已经进入实际批阅请求。

数学 v2 返回的是评分点与学生证据的映射候选，例如：

```json
{
  "rubric_point_id": "q15-part1-regression-slope",
  "status": "supported",
  "evidence_ids": ["student-step-3", "student-formula-2"],
  "confidence": 0.94,
  "reason_code": "verified_regression_slope"
}
```

这是响应中的单个元素示意，不是完整请求或响应。`evidence_ids` 必须引用本次学生答卷的真实证据；示例 ID 不可照搬。状态为 `supported`、`contradicted`、`uncertain`；模型不得创造评分点或直接决定最终分数。

### 6.2 建议扩展的数据分层

应区分三层，避免把“生成草稿”和“传 AI”做成同一张无约束表：

1. **配置层**：子问、评分点、分值来源、解析依据、草稿/确认状态、生成模型版本、人工修订和评分依赖。
2. **阅卷输入层**：冻结题目、参考答案/解法、评分点和学生证据。只映射 AI 判断需要的字段；内部数据库信息继续留在服务端。
3. **阅卷输出层**：点 ID、支持/矛盾/不确定、证据引用、解释和置信度；服务端按正式规则计算与校验分数。

配置层建议增加：`subquestion_id`、`criterion_type`、`depends_on`、`partial_credit_levels`、`follow_through_policy`、`alternative_group`、`source_refs`、`origin`、`review_status`。这些是**新增设计**，现有严格契约尚不接受。

教师原解析的 `source_refs` 与学生答卷的 `evidence_ids` 是两个不同来源体系：前者说明为什么设这个采分点，后者说明学生为什么获得或没有获得这个点。

同一“得分目标”可以有多个满足条件，使用 OR 条件表达不同解法；不要为每条解法复制一组累加评分点。若必须建立完整互斥路径，按每个子问的合法路径计算，所有路径最大可得分都应等于该子问满分，最后只能选用一个有效路径。

对当前公式证据 DSL，应生成具体数学目标，而不是只填“出现任意有效变形”“得到某个最终结果”；否则即使有步骤图也无法确定学生是否满足这个评分点。

发布时同时冻结题目/答案/解析/评分点和规则版本。运行中的 AI 批阅必须使用冻结快照，不能一边阅卷一边重新从资料生成评分标准。

### 6.3 当前数学 AI 的真实能力边界

`mathunderstanding/scorer.go` 不会根据模型返回的 `supported` 直接把采分点判为已得分；它合并证据引用，标记 `model_candidate_requires_review`，服务端原有未决状态保持不变。`concept`、`unit`、`domain` 等证据当前也仍需复核。

因此，新增评分草稿之后，还必须明确产品所承诺的批阅范围：符号验证或冻结数学目标可以结算的点由规则处理；语义证明、替代解法、错误延续等目前继续形成教师建议。若要扩大自动结算范围，需要实现新规则的计分语义、验证和校准，而不只是把更多字段交给模型。

当前评分点内部是满分、零分、未决三态，短期要表达部分得分应拆分独立可判断的细点。`allow_partial_total=false` 表示所有点的满分之和必须覆盖题目满分，不是禁止学生取得部分分；`required` 也不是前后采分点依赖。未来增加分档或依赖时必须升级评分器和协议。

数学 `evidence_requirements` 保存在服务端，但没有作为字段投影到当前 AI 的 `rubric.points`。既有 `final_result` 目标匹配也不能被描述为任意代数等价证明。应保留当前协议版本，在新版本里明确参考解法、依赖、替代路径、分档与证据要求的语义。

## 11. 并行复核补充：保存、冲突与布局

### 保存内容丢失风险

三个编辑器分别持有题目表单、评分细则和客观规则状态；保存题目或细则会重新 `loadConfig`。随后 `selectedQuestion` 新对象触发三个编辑器各自的初始化 effect，覆盖未保存内容。因此先同时修改答案和评分点，再只保存其中一处，另一处修改有丢失风险。

资料校对的 `usePaperImportWorkflow` 同样在 `paperImports` 变化时整体重置 `reviewDrafts`，没有 dirty 字段或并发冲突保护。需用稳定题目ID、generation/revision和本地dirty字段统一管理草稿；后台返回新结果时三方合并，而不是用新数组直接覆盖。此项为代码链路确认的风险，未在用户考试中执行破坏性复现。

### 追加资料和子问匹配

追加资料按题号替换旧候选，而非保留字段级冲突；同轮相同答案仍可能被当作重复错误，多份同题解析则无法唯一挂载且缺少明确冲突提示。建议同内容合并来源，不同内容保留候选并让用户在同题上下文核对。

候选里有子题提示，但匹配没有完整组合父题和子问标识，草稿也没有层级字段。应以稳定父子ID贯通答案、解析步骤、评分点和答题卡题块，不靠一条长文本中的“（1）（2）”猜关系。

### 跳转、宽度和规则表单

嵌入的资料路由不渲染 `paper-question-summary`，但已导入卡片“去逐题校对”只滚动到该ID，缺少实际路由跳转；应修为打开工作台并选题。

CSS中的最大考试画布1180px，准备侧栏184px、间距24px，再加题目侧栏320px、间距16px，详情区只剩约636px，尚未扣内边距。公式采分表的固定列宽不含描述已经680px；四列客观规则也不适合这个内层宽度。用户所见的窄长区域具有明确布局原因。建议校对时收起准备侧栏，题目导航约220–260px，并按实际内容容器宽度适配。

数值误差还有两套编辑源，一处以百分比展示相对误差，另一处以0–1展示。需统一权威数据源和百分比界面，避免不同表单互相覆盖或单位误解。

这些尺寸是源码推导，未对当前浏览器做像素测量。实施后需在真实页面验证滚动、聚焦、缩放与保存操作。
