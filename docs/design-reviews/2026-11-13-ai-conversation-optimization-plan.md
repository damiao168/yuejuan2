# AI 对话上下文与缓存完整优化方案

统一学校助手已实施预算保护、来源记忆和公开网页缓存优化。兼容聊天接口采用同一模型窗口与计数策略。真实模型对照评测待提供专用配置。

## 1. 目标与不可破坏的边界

改善长对话连续性、容量利用率、模型调用成本和公开资料读取效率，并让失败原因可解释。模型窗口、一次提问的累计用量、浏览器显示历史、供应商前缀缓存分别管理。

- 租户、学校和资源权限仍由服务端当前身份及业务工具校验；记忆与历史只作不可信材料，成绩和发布状态每轮核实。
- 公开联网只接收连续公开问答；校内历史、附件及普通会话记忆不能借路由进入公开搜索。
- 业务会话保持原保存边界，不新增服务端正文数据库；公共电脑、账号切换、取消、刷新恢复仍沿用既有隔离规则。
- 当前问题、系统约束与本轮工具调用/结果不得被拆开；不足时准确拒绝或解释已完成范围。
- 保留工作区原有修改。第三方具体文件、版本和许可逐项记录；依赖走正式包管理，生成契约从权威 OpenAPI 生成。

## 2. 容量与单轮预算

新增独立的模型上下文不足、单轮累计额度不足错误。容量检查先独立判断必须保留内容是否能进入模型窗口，再检查剩余单轮额度；二者不得相互冒充。单轮仍为 60000 usage tokens 的软阈值，不能描述为精确费用上限。

普通学校助手为探针、工具规划和最终回答分别限制输出。规划前按已知材料预留最终回答所需额度，最终回答接近额度时允许缩短输出。公开搜索走独立的动作编排，采用模型窗口和剩余额度。兼容聊天接口采用相同窗口与计数策略。

计数器按显式配置选择，支持经过许可核验的离线 tokenizer；不按模糊模型名称猜测编码。未知模型保持保守兜底。工具 schema、消息协议和图片均纳入预算；多模态总量仍标记估算。计数结果在一次请求内复用，避免每裁一轮重新编码全部文本、解码相同图片。日志记录方法、估算、真实 usage、偏差、裁剪和拒绝原因，不记录正文或凭据。

验收：短输入/低剩余额度、大附件/充足剩余额度分别得到正确错误；探针、规划、回答各阶段预算不串用；中文、英文、代码、JSON、工具和图片均有计数案例；无效配置/超限零外发；裁剪后协议配对有效。

## 3. 可追溯的会话记忆

将仅保留固定头尾的摘录升级为带来源标识的有界记忆。保存用户原文片段、来源消息标识与顺序，区分自动选取和用户明确保留；按当前问题相关性、用户更正/撤销、早期目标和近期要求选择。条数与总容量双重限制，不把简单关键词抽取宣称为语义理解。

记忆通过独立客户端字段提交并严格校验，进入模型时保持普通不可信用户材料身份。服务端为记忆分配独立小预算；裁旧轮时先保留可容纳的记忆，必要时缩减记忆，再准确提示省略。相冲突的历史必须携带顺序，最新明确更正优先；不得静默将过时约定合成为事实。原文来源保留以便核对，无法证明来源存在时仍视作客户端材料。

旧版摘录可迁移。用户能够显式保留或移除关键要求，自动记忆仅选择用户原文。公开模式拒绝接收普通记忆。当前保留可检查的原文片段，避免为摘要增加一次模型调用。

验收：重要要求位于长消息中部、跨多轮追问、更正/撤销、主题切换、窗口收缩、旧缓存迁移、账号切换、公开模式、业务标记和公共电脑都有行为测试。测试验证最终输入的含义与边界，不仅判断一个字符串是否出现。

## 4. 减少重复模型调用

保留当前工具授权和输出校验。增加可回退的直接回答路径：只有规划已完整结束、没有工具调用、回答未截断且通过现有答案检查时，才允许复用该响应；不把完整返回模拟成逐字流，不重放隐藏思考，不再额外生成相同回答。工具证据下发和总用量保持一致。

该路径通过服务端配置开关控制，并与原二次生成路径对比。离线测试证明响应有效与调用次数减少，真实模型评测再决定默认启用范围；无数据时保留保守默认。工具响应格式、模型拒绝、空回答和取消不能进入成功缓存或完成事件。

自动化测试核对完成事件、调用次数、用量和回退路径。真实模型调用用于比较总延迟、tokens 和质量。首字延迟使用学校助手的流式接口测量。

## 5. 缓存与并发

继续限定为匿名公开搜索/网页缓存，保留 URL/SSRF、HTTP 禁止存储、原读取时间及大小边界。先增加缓存命中/未命中、驱逐、在途重复、条数/字节和读取耗时观测，再实现有界同键冷请求合并。

合并任务使用独立且有时限的读取上下文；一个等待者取消只退出自身，全部等待者取消才终止读取。失败不缓存，实例关闭与超时释放在途项，禁止无界后台任务。并发数与在途键均有上限；达到上限明确退化或拒绝。条件再验证与共享 Redis 作为负载触发项：命中率、跨实例重复与更新频率没有数据前不直接增加部署依赖。

验收：相同 URL 同时请求只触发一次正常读取；取消一个不影响其他等待者；全部取消能停止；失败可重试；不同 URL 可并行；到期、容量和 SSRF 行为不退化。性能基准记录冷/热/突发负载结果。

## 6. 评测与交付门槛

评测脚本包含 12 个合成文本用例，覆盖约束、更正和跨主题问答。多图、工具执行、公开与校内隔离、失败和取消由 Go 与前端测试覆盖。

提供真实供应商评测入口，只从显式环境配置读取端点和凭据，默认不外发。设置请求数、超时和 token 上限；输出聚合指标与脱敏案例 ID，不输出凭据和敏感正文。记录模型版本、预算策略、计数方法和配置指纹，允许对照旧路径。没有凭据时结果明确为未执行，不伪造质量/价格/命中率。

真实对照按相同模型版本和输出上限比较两条路径的回答及用量。脚本测量非流式总延迟，学校助手的首字延迟与工具质量通过真实流式链路复核。质量和成本有实测结果后再决定是否启用直接回答。公开缓存通过进程内并发测试验收，公网收益按实际运行数据判断。

## 兼容性与成熟源码复用审查

实际纳入的离线计数器复用 `tiktoken-go/tokenizer v0.10.0`，正则复用 `regexp2/v2 v2.5.1`；读取并发上限复用 Go 官方 `x/sync/semaphore v0.24.0`。源码已下载审读，版本由 Go 模块文件固定，MIT/BSD 通知随运行镜像交付。LangChain/LangMem 等项目用于对照消息边界和记忆设计，未把 Python 编排框架整体迁入 Go 服务；带额外许可条件的 Open WebUI 仍只作设计参考。

新增 `memory` 是可选请求字段，旧客户端请求继续有效；公开模式禁止携带该新字段。新增 `context` SSE 帧没有正文，旧网页实现会忽略未知帧但仍按序号推进；新 SDK 与界面消费预算反馈。原有完成、错误和工具帧保持结构。组合约束由保守契约门禁拦截后，按上述兼容规则显式审查，仅通过正式生成入口的 `--schemas` 参数更新本批 10 个 schema 的基线，不接受工作区其余未审读契约变化。对应生成器测试保证其他操作和 schema 的保护仍保留。
