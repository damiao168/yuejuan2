# S04 — 评分、主观题、证据与数学理解

## 结论

1 项疑似产品／路由不一致，另有 1 项静态并发风险与 S05-F01 的评分运行终态问题重合。没有新增运行时复现；本轮不连接数据库或启动服务。

## 发现

### S04-F01 — 评分准备将 AI 主观题视作有自动辅助路径，但常规评分运行只创建空白人工任务

- **等级：疑似，建议 P2。** 行为本身由代码直接确定；是否违反产品意图有不确定性，因为系统另有显式 subjective batch API。
- **位置：** `services/api-gateway/internal/paper/scoring_coverage.go:21-35` 将 `short_answer`、`calculation`、`essay`、`discussion` 列为 AIAssistedQuestionTypes，且把有此类路径的类型排除在 manual-only 清单外。`paper/template_validation.go:211-233` 只对没有任何自动路径的题型显示“100% 由人工评阅”提示。`services/api-gateway/internal/grading/scoring_run_routing.go:40-60` 只将填空／数值送规则输入、将选择题送 OMR，其余可走 AI 的题型落入 `rule_review_required` 人工任务。`scoring_run_start.go:198-201,208-324` 持久化该任务；`grading/handlers.go:269-281` 在启动评分后只调用 `ProcessRuleCandidates`。独立的 subjective batch 入口注册在 `server/routes_grading.go:31-36`，但常规 StartScoringRun 调用链没有创建或 enqueue batch。
- **触发条件：** 试卷包含通过 readiness 的 essay/short-answer/calculation/discussion 题，管理员通过 `/api/v1/exams/{examId}/scoring-runs` 启动常规评分运行。
- **实际结果：** 该题在常规评分运行中直接成为 `rule_review_required` 人工任务，没有由该运行生成 AI suggestion。准备 advisory 不提示这些题的常规运行会先走人工空白阅卷。
- **后果：** 运维按“自动评分运行”操作时，AI 辅助题会被整体送人工；这可能增加工作量，且准备时没有明确揭示这一常规路径。`scoring_coverage.go:21-23` 的注释描述这些类型由 reviewer 从 suggested score 开始，与该调用链结果不吻合。
- **证据等级／疑点：** route、handler 和 batch API 的静态调用关系支持上述结果；没有用运行时服务验证。如果产品流程要求管理员另外手动创建／enqueue subjective batch，则属于 UI／流程提示不足而非评分路由缺陷。建议确认预期：要么启动评分时集成 AI batch，要么 readiness 明示普通评分运行不触发该辅助路径并修正文档性注释。

### S04-F02 — 自动规则候选处理存在取消最终化后的终态覆盖交错（疑似；与 S05-F01 重合）

- **等级：疑似，未独立复现；建议并入 S05-F01 的终态保护修复，而不是重复计数。**
- **位置：** `services/api-gateway/internal/grading/scoring_run_process.go:7-15` 只在处理开始时读取一次 run 是否 active，随后在 `:36-67` 跨请求处理各候选并创建 grade／review task。`scoring_run_omr.go:401-419` 的 `ConfirmRuleGrade` 锁 answer_segment，但不检查关联 run 仍为活动状态；`:447-463` 插入当前 grade 并按 ID 更新 run，状态更新没有排除 cancelled。相反，`scoring_run_lifecycle.go:63-105` 会把取消 run 的 review task 置 cancelled、run 置 cancelled 且计数归零。
- **触发条件：** ProcessRuleCandidates 首次 active 检查后暂停；另一个具备 `grading:manage` 权限的请求完成取消最终化；先前处理随后继续确认候选或插入复核任务。
- **可能后果：** 终态 run 可能再次写入 current grade、从 cancelled 改为 completed，或取消事务完成后再出现关联人工任务。取消后人工重分派导致终态复活已有运行时证据见 `S05.md` S05-F01；此处是自动候选写入交错，未单独实测。
- **建议验证：** 通过 production Postgres router 并发屏障测试，在候选查询后暂停处理，取消并 finalize，再恢复处理；断言无新增 current grade/task 且 run 保持 cancelled。
