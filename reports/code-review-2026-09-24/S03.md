# S03 — 文件、采集、上传、提交与切片

## 结论

在已追踪的 production router → service → PostgreSQL store 路径中，未确认跨租户读取、上传内容替换或非原子完成缺陷。对象资源边界中存在的 uploader fallback 未发现可从生产文件路由绕过 exam/school/submission 范围的证据。

## 覆盖与证据

- 路由和 scope：`services/api-gateway/internal/server/routes_capture.go:23-24` 将 capture upload routes 包在 `requireCaptureManage` 下；`router_guards.go:81-85,100-106` 对认证请求应用 `RequireRequestResourceBoundary`。`auth/resource_scope.go:130-155,191-221` 解析并执行数据库对象边界。`files/types.go:156-176` 的 `AllowsAsset` 先约束 tenant、file/school/exam/submission/student，再处理 actor 上传者回退；未发现 production handler 可凭 actor ID 绕开边界。
- 分块上传：`internal/captureupload/service.go:41-64,67-88` 校验批次与 exam 一致、拒绝已完成／已取消批次，并验证每个 chunk 自身 SHA-256、大小与偏移。Postgres `store_postgres.go:92-150` 通过 tenant 条件、会话锁、连续 offset 以及上传中状态落盘；重复 offset 需要既有 hash/大小匹配。
- 完成与恢复：`service.go:91-166` 先获取 finalization lease，校验完整 persisted chunk 序列总 hash 和 MIME sniff，再物化文件、激活 asset、注册 capture file、完成 session。`store_postgres.go:153-254,274-315` 用 tenant、finalizing 状态和 completion token 锁住终态写入；完成与删 chunks 在一个 SQL transaction 中，旧 lease 不能覆盖新 lease。
- 提交／切片：抽查 submission、answer-segment 与 capture registration/correction Postgres 查询，相关读写均使用 tenant 过滤，跨表 JOIN 同时匹配 tenant ID；切片使用当前页面／模板版本和 crop 内容哈希。

## 未确认的小行为

`captureupload/service.go:67-79` 对 completed session 的重传，只要 chunk 自身 hash 正确且 offset 小于 confirmed offset，就返回 completed session；完成后服务已删除 chunks，因此服务层并未比较该重传内容与历史内容。当前分支只回报成功且不改变任何数据，未证实会覆盖对象或污染提交，故不列为缺陷。客户端可能把不同字节的旧 chunk 误认为成功重试。

## 限制

未连接数据库、对象存储或启动服务；没有进行运行时多租户隔离测试。覆盖集中于上传完成及其与 capture/file store 的事务边界，不等同于穷尽所有 capture registration、OCR、导出与切片 SQL。
