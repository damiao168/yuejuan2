## S08-F01 — 桌面端退出登录未吊销服务端 bearer session

- **优先级：P2**
- **位置：** [useDesktopSession.ts](../../apps/desktop-client/src/features/session/useDesktopSession.ts#L146) 行 146–157；[auth.ts](../../apps/desktop-client/src/api/auth.ts#L10) 行 10–19；[routes_auth.go](../../services/api-gateway/internal/server/routes_auth.go#L19) 行 19；[handlers_session.go](../../services/api-gateway/internal/auth/handlers_session.go#L14) 行 14–36。
- **触发条件：** 用户在桌面端使用 bearer token 登录后点击“退出登录”。
- **预期依据：** 显式登出应使当前 session 在服务端失效。服务端已有 `POST /api/v1/auth/logout`；`Logout` 从 bearer header 读取 token 并删除 session。Go 测试 `TestLoginMeLogout` 也验证：bearer logout 后使用相同 token 调 `/auth/me` 应得 401。
- **实际行为：** 桌面 `handleLogout` 只递增本地登录尝试代次、清除 React token/user 与 durable session 状态、清理本地持久会话并记录事件；桌面 `api/auth.ts` 只有 login 和 getCurrentUser，没有 logout API 调用。服务端 session 记录未被删除，原 token 仍可在有效期内通过其他持有该 token 的客户端请求。
- **影响：** 本机 UI 虽然退出，但已复制/泄露的 bearer token 仍保持可用，直到过期或被服务端主动撤销；用户也无法通过桌面登出完成期望的会话吊销。
- **证据 / 复现：** 用测试用户登录，保存一个测试环境的 bearer token，调用桌面退出后，以该 token 请求 `GET /api/v1/auth/me`；按当前实现，若未过期，服务端 session 仍在。服务端 `handlers_test.go:91–121` 展示的 bearer logout 路径会使相同验证返回 401，而桌面路径未触发它。
- **已排除的保护：** 本地退出会清理桌面凭据状态与持久会话绑定；这可阻止该应用继续自动使用 token，但不触及服务端 session。Token 自身到期、logout-all 或管理员撤销只能缩短暴露期，不等价于此次退出即撤销。
- **疑点：** 桌面 token 当前仅在前端状态中使用，退出后是否仍有其他本地持久副本需看具体 credential-store 流程；无论如何，服务端 session 不会因这些本地操作删除。
- **修复方向：** 在清空 token 前用当前认证 client 调用 `POST /api/v1/auth/logout`，并在网络失败时仍可靠地清除本地状态；定义并展示服务端吊销未确认的结果。添加桌面 hook/API 测试验证调用带 bearer token，并通过服务端集成断言 token 随后无效。
