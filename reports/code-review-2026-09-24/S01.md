## 结论

当前工作区中，在本专项已追踪的生产入口与 PostgreSQL 路径上**未确认可复现缺陷**。未提交代码及当前 174 份迁移均纳入定位；`docs/code-review-context.md` 仅作架构导航，不用旧 HEAD 的包数、迁移数或风险描述作结论。

## 生产链与保护核对

- 生产图由 `internal/server/server.go` → `application_modules.go` → `application_stores.go` 装配；`NewPostgresApplicationStores` 分别注入 `auth.NewPostgresStore`、`org.NewPostgresStore`、`platformschools.NewPostgresStore`，不是 Memory 语义。Memory stores 只作对照。
- 入口核对：`internal/server/routes_auth.go`、`routes_org.go`、`routes_platform_schools.go`、`routes_onboarding.go` 及 `router_guards.go`。账号／组织写入口有权限守卫；平台学校读入口统一经过 `requirePlatformSchoolRead`（`RequirePlatformAdmin` 与 `tenant:manage`）；Onboarding readiness 由其专用读取守卫包裹。
- 身份／访问范围核对：`internal/auth/middleware.go`、`context.go`、`access_scope.go`、`resource_scope.go`、`role_policy.go` 与 `store_postgres.go`。Postgres `ResolveAccessScope` 根据数据库中的角色、组织关系、已分配任务生成范围，服务端请求数据不能直接写入 `AccessScope`；集合资源需要仓储应用查询范围，租户 ID 贯穿各查询。
- 组织主数据核对：`internal/org/handlers.go`、`store_postgres.go`、`enrollment_postgres.go`、`readiness.go`。写学校／年级／班级／学生、转学与教师绑定时，关联对象查询同时带 `tenant_id`，创建 enrollment 与学生班级更新处于同一事务；跨学年转学不会只改展示字段。
- 平台／引导读取核对：`internal/platformschools/{handlers,service,store_postgres}.go`、`internal/onboarding/{handler,service}.go` 与对应 PostgreSQL reader。跨租户平台路径只由受限平台路由进入；组织租户列表的“列出全部”条件也再次在 Handler/Store 侧由平台租户和权限控制。迁移 `000108*`、`000139*`、`000143*`、`000165*` 中的平台视图／授权按只读用途核对，未发现它们替代业务写授权的路径。

## 重点排查与未确认项

检查了会话租户来源、角色／权限 JOIN、直接资源与列表范围、学生 enrollment 所属学校、平台学校路径及低敏平台投影授权。没有发现由 body/path 中的外部 tenant ID 改写认证租户、或普通租户调用平台学校路由的证据。由于本任务禁止连接／操作数据库，本报告不声称验证了现场 RLS 状态；生产结论基于当前应用 SQL 与迁移。没有将未读的每个 MFA／登录恢复边界都视作本轮已穷尽。

另对主控补跑报告中的 PostgreSQL E2E 失败做了代码复核，**不作为生产缺陷**：`TestTeacherAccountSecurityE2EWithPostgres` 在 `internal/server/e2e_auth_security_test.go:196-199` 将重新认证时间设为 20 分钟前，再期待 credential-reset 被拒；但当前配置默认 `EDUGRADE_RECENT_AUTH_TTL=1h`（`internal/config/config.go:221`），`RequireRecentAuth` 依据注入 TTL（`internal/auth/step_up.go:12-30`）。该断言与当前有效策略不一致，HTTP 201 符合实现。相邻重新认证后的敏感重置流程仍有执行，但该过期分支目前没有验证到默认阈值；建议修正 fixture 使用 >1h，或为该测试明确设置短 TTL。
