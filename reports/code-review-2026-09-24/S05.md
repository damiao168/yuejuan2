# S05 — 人工复核与阅卷质控

## 结论

确认 1 项缺陷。`POST /api/v1/scoring-runs/{runId}/cancel` 已把任务和运行标为 `cancelled` 后，管理员仍可把原任务重新分派给阅卷人；阅卷人提交后会生成当前有效的人评分，并把原 `scoring_run` 从 `cancelled` 改为 `completed`。这使取消操作失去终止语义，评分数据可能再次进入后续发布。该路径已由主控在隔离 PostgreSQL 17、应用全部迁移、真实 production router 上复现；diagnostic test 的 PASS 表示缺陷确实发生。

## 发现

### S05-F01 — 取消的评分任务可重新分派并复活评分运行

- **优先级：P1**。评分运行取消后，底层人工任务可经正常公开管理端点重新激活并提交；写入的是 `question_grade.is_current=true,status='confirmed'`，而且原 run 状态被覆盖成 `completed`。这会把用户明确终止的评分重新纳入当前评分事实，影响后续成绩及其质量追踪。
- **位置／生产路径：** `internal/grading/scoring_run_lifecycle.go:94-100` 在 `FinalizeScoringRunCancellation` 的同一事务中，将该 run 的活动任务置为 `cancelled`、清除 assignee / claim，然后把 run 置为 `cancelled` 并把计数归零。取消 HTTP 入口为 `internal/server/routes_grading.go` 中 `/api/v1/scoring-runs/{runId}/cancel`，处理器 `internal/grading/handlers.go:342-372`；只有运行中的 OMR worker 全部结束后才会 finalize。
- **触发条件：** 运行已有 `pending/assigned/in_progress/returned` 的单评任务，取消成功后，具备 `review:manage` 的操作者调用 `/api/v1/review-tasks/{id}/assign`，传入新阅卷人和取消时递增后的 `expected_revision`；该阅卷人之后调用 `/api/v1/review-tasks/{id}/submit`。真实复现使用一个合成 single-choice 题和 OMR 结果 `needs_human_review=true`，确保 worker 已结束且任务待人工处理。
- **预期依据：** 取消处理明确把活动 task 与 scoring run 标为终止状态（同上）；因此对已取消的 task，分派／提交应返回冲突，取消运行不应再产生其 current grade。
- **实际行为与代码证据：** `internal/server/routes_review.go:37,45,49` 将单项／批量分派交给 `requireReviewManage`，提交交给 `requireReviewWork`。`internal/review/handlers.go:170-203` 校验调用者与新阅卷人权限，但没有检查任务状态。Postgres `AssignTask` 和 `BatchAssignTasks`（`internal/review/store_postgres_tasks.go:196-198,233-235`）只排除 `submitted`、`completed`，故 `cancelled` 满足 UPDATE 条件并被改成 `assigned`。提交路径锁住该 task、校验 assignee、revision 及 `canSubmit`（同文件 `257-283`；允许状态见 `internal/review/store_memory.go:1040-1047`）；由于刚被分派，状态已经是 `assigned`，这些检查都会通过。对 `grade_round='single'` 的任务，`store_postgres_tasks.go:329-335` 插入新的当前 `question_grade`；随后 `:352-355` 的 run 更新没有过滤旧 run 状态，仅按 linked `review_task.scoring_run_id` 扣 review count／加 human count，并在 queued/review/failed 为零时改成 `completed`。
- **复现证据：** 主控用诊断源码 `reports/code-review-2026-09-24/review_cancel_repro_test.go:14-60`，经 Go overlay 接入 `internal/server` 测试包；`reports/code-review-2026-09-24/repro-cancelled-run.log` 记录 `/cancel` 后 task 为 cancelled、HTTP assign 返回 200、submit 返回 201、run 由 cancelled 变 completed，且有 1 条 current confirmed grade。测试依赖合成数据和隔离 PG17；PASS 是成功触发缺陷，并非期望行为通过。
- **已排除的保护：** 取消时会等待活动 worker 收尾；复现未绕过 worker lease，而是在 worker 正常提交 OMR 结果并退出后取消。分派／提交均使用认证身份、tenant 条件、阅卷人权限与 revision；这些确保了合法管理员对本租户正确版本的写入，但不阻止从 `cancelled` 复活。迁移 `000038_story056_scoring_recovery.sql:12-13` 仅以 CHECK 列举允许的状态值，其中包括 `cancelled`，未见阻止该状态转移的 review_task trigger 或其他数据库状态机约束。
- **疑点／修复方向：** 当前行为可能与显式撤销后重新开工的运维意图混淆；若业务要恢复，应通过新的 scoring run / 显式恢复流程保留取消 run 的终止审计。最小修复是 Postgres 单项和批量分派 SQL 均排除 `cancelled`，并令 SubmitGrade 在写 grade 前拒绝与 cancelled scoring run 关联的 task；同时确保 cancelled run 不被提交事务改写。增加真实 PostgreSQL 回归用例，断言取消后 assignment 和 submit 均为冲突，原 run 保持 cancelled，且不新增 current question_grade。
