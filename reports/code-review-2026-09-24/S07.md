## S07-F01 — 切换考试时学生范围和准备检查可能被旧请求覆盖

- **优先级：P2**
- **位置：** [ExamPreparationPage.tsx](../../apps/web-admin/src/pages/ExamPreparationPage.tsx#L49) 行 49–59、61、66–75、115–125、129–149；[AppShell.tsx](../../apps/web-admin/src/AppShell.tsx#L246) 行 246–258。
- **触发条件：** 用户在同一个学生范围或设置视图中快速从考试 A 切到考试 B，A 的请求晚于 B 返回。AppShell 按路由参数重新传入 `examId`，但这两个视图没有 `key={examId}`，组件状态会复用；`load` 也没有请求代次或当前 ID 校验。
- **预期依据：** 当前视图的考试数据、可编辑班级范围与确认动作必须始终属于 URL 中的考试；较早请求返回后不得替换较新的考试状态。
- **实际行为：** `ExamStudentScopePage.load` 在 Promise.all 后直接写入 exam/classes/grades/selected。A 返回较晚时可把 A 的考试对象和班级选择放进 B 的页面；`save` 使用状态中的 `exam.id`，可能把用户在 B 视图中的编辑保存回 A。准备页也会让旧 readiness 覆盖状态，而确认/开始操作使用当前闭包的 `examId`，界面所展示的检查结果可能与实际操作考试不一致。
- **影响：** 管理员可能误改另一场考试的参与班级，或基于错误的准备状态确认/启动当前考试，造成名单范围及流程状态混淆。
- **证据 / 复现：** 两个 `load` 回调均只依赖 `examId`，但异步结果没有在写状态前对其进行比较。AppShell 的 `students` 与 `settings` 分支直接挂载组件且未设 key。组件级诊断测试 `reports/code-review-2026-09-24/repro-preparation-race.test.tsx` 使用受控延迟：先挂载 A，立即重渲染为 B，让 B 先返回、A 后返回；随后在 B 路由的组件点击保存，实际调用 `updateExam('A', ...)`。两项诊断测试均通过，详见 `repro-preparation-race.log`。
- **已排除的保护：** 页面有权限门控和后端 `updateExam(exam.id, ...)` 的版本号参数，但它们不解决客户端将 A 数据显示在 B 路由、或将编辑提交给 A 的问题。其他捕获页面有按租户/用户/考试设 key，说明这里并非统一依赖挂载重置。
- **疑点：** 后端是否会因操作者对 A 缺少权限而拒绝该误提交，取决于具体权限；即使拒绝，错误状态展示和对有权管理 A 的用户造成的数据写入仍成立。复现为组件级测试，未运行该具体路径的完整浏览器测试。
- **修复方向：** 切换 ID 时立即清空旧考试状态，并对读请求结果和后续写操作校验捕获的 `examId`/请求代次；或按考试 ID 对页面内部状态重新挂载。保存与刷新名单动作需确认状态中的考试 ID 仍等于当前路由 ID。

## S07-F02 — 考试创建的浏览器断言仍期待旧的设置路由

- **优先级：P2（CI 阻断）**
- **位置：** [CreateExamPage.tsx](../../apps/web-admin/src/features/exams/create/CreateExamPage.tsx#L19) 行 19–21；[dashboard-workbench.spec.ts](../../tests/e2e/specs/dashboard-workbench.spec.ts#L81) 行 81；[exam-command-recovery.spec.ts](../../tests/e2e/specs/exam-command-recovery.spec.ts#L35) 行 35、55。
- **触发条件：** 执行当前 Playwright 浏览器套件中的快速/方案考试创建和命令恢复路径。
- **预期依据：** 创建成功后的非资料模式现在被有意路由到学生范围页面；相关端到端断言应跟随当前路由契约，避免将有效行为判为失败。
- **实际行为：** `completionPath` 返回 `/students`，但上述三个断言仍期待 `/settings`。主控提供的当前浏览器套件日志显示这三例重试后仍失败，浏览器实际地址均为 `#/admin/exams/exam-created-math/students`；70 例通过、3 例失败。因此测试没有验证后续流程而使 CI 失败；日志并未显示考试创建请求失败。
- **影响：** CI 继续失败，阻止依赖该门禁的合并；不能据此认定创建事务或命令回执恢复失败。
- **证据 / 复现：** `reports/code-review-2026-09-24/playwright.log` 中三个失败的期望/实际 URL 和失败定位；`dashboard-workbench.spec.ts:81`、`exam-command-recovery.spec.ts:35,55` 的断言与 `completionPath` 返回值直接冲突。
- **已排除的保护：** Playwright 重试再次得到同一 URL，符合稳定的路由变更；其他新增工作区用例已经断言学生范围入口。测试门禁捕获了不一致，但当前仍红。
- **疑点：** 本报告依据主控提供并保存在工作区的浏览器套件结果，没有在本专项重复运行浏览器套件。
- **修复方向：** 更新三个 URL 断言到当前学生范围路径，并在 dashboard 用例中继续验证创建后的实际准备页面及其后续导航。

## S07-F03 — 跨年级选择班级会丢弃其他年级的已选班级

- **优先级：P2**
- **位置：** [ExamPreparationPage.tsx](../../apps/web-admin/src/pages/ExamPreparationPage.tsx#L98) 行 98、100。
- **触发条件：** 一场考试已有年级一的班级 A；管理员在学生范围页勾选年级二的班级 B，随后保存。
- **预期依据：** 应保存 A 与 B 两个班级，因为用户没有取消 A。
- **实际行为：** 每个年级渲染一个独立的 Ant Design `Checkbox.Group`，但各组共用全局 `selected`。每组的 `onChange` 直接用该组返回的值覆盖全局列表。Ant Design 组组件只返回当前组已注册的选项，因此在年级二勾选 B 时，年级一的 A 被删除；保存请求只发送 B，可能从考试范围及后续冻结名单中移除 A。
- **证据 / 复现：** 组件级诊断测试 `reports/code-review-2026-09-24/repro-preparation-race.test.tsx` 构造 A 已选、B 未选，点击 B 后观察 A 变为未选，并验证 `updateExam('C', { class_ids: ['g2-class'], expected_revision: 1 })`；测试通过，详见 `repro-preparation-race.log`。`node_modules/antd/es/checkbox/Group.js:69` 确认输出只保留本组注册的值。
- **修复方向：** 把所有班级置于同一个 `Checkbox.Group`，或各组 `onChange` 时仅替换当前组的 ID、保留其他组的已选 ID；增加跨年级选择/保存的回归测试。
