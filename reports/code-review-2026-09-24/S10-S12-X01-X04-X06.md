## S10／X01／X04-F01 — Worker 租约把请求头当作服务身份，允许跨 Worker 队列领取并读取任务数据

- **优先级：P1。** 需要一个已认证的 `page_processing_worker` 服务账号及同租户中待处理的另一 Worker 任务；不是未认证调用，也没有证据表明可跨租户领取。
- **位置：** [`routes_worker.go`](../../services/api-gateway/internal/server/routes_worker.go#L11) 行 11–18、31–36；[`router_guards.go`](../../services/api-gateway/internal/server/router_guards.go#L284) 行 284–288；[`000028_story055_page_processing_role.sql`](../../services/api-gateway/migrations/000028_story055_page_processing_role.sql#L6) 行 6–12；[`handlers.go`](../../services/api-gateway/internal/workerruntime/handlers.go#L47) 行 47–67；[`store_postgres.go`](../../services/api-gateway/internal/workerruntime/store_postgres.go#L214) 行 214–230、269–286；[`scope_middleware.go`](../../services/api-gateway/internal/workerruntime/scope_middleware.go#L111) 行 111–137；[`handlers_batch.go`](../../services/api-gateway/internal/subjective/handlers_batch.go#L155) 行 155。
- **触发链：** `page_processing_worker` 的迁移授权包含 `ocr:manage` 和 `file:manage`。共享 Worker claim/read/execute 路由分别接受 `ocr:manage` 或 `orchestrator:manage`。Claim 请求只验证 `queue_name`、`worker_service`、`worker_instance_id` 非空；Postgres 领取查询按当前 tenant 与请求的 queue 选任务，然后把请求提交的 `worker_service`／instance 写进租约。调用者可用 `queue_name=subjective-grading`、`worker_service=subjective-grading-worker` 领取同租户的主观评分任务。
- **保护缺口：** `TaskScope` 从请求头读取 worker service 和 instance，只要求它们与数据库租约记录相同；它没有把 `worker_service` 绑定到已认证用户的角色、用户名或其他服务身份。现有 [`scope_middleware_test.go`](../../services/api-gateway/internal/workerruntime/scope_middleware_test.go#L86) 行 86–95 甚至构造了 `page_processing_worker` 用户与 `ocr-worker` 租约头的组合，并让它进入受保护 handler；该测试用于检查租户／资源 capability，未覆盖 Worker 身份绑定。
- **可验证影响：** 主观评分 runtime task 的 payload 含 `answer_segment_id`。服务 Worker 可在取得租约后调用 `/api/v1/internal/answer-segments/{id}/image`：路由只要求 `ocr:manage`，`RequireTaskPayloadValue` 只检查 segment ID 是否出现在该任务 payload 中，随后 `GetImage` 通过 tenant、segment 和 active crop 证据读取对象。因而被错配身份的 Worker 可以读取本应交给主观评分 Worker 的学生答题裁剪图；它也能占住评分任务租约并延迟正常 Worker。主观评分的 execute/result 路由同样只要求共享 `requireWorkerExecute` 加 source/租约检查，未额外验证登录服务身份，所以该账号还能以被冒用的租约调用该 Worker 操作链。评分输出仍要求人工复核；本报告不声称模型结果可直接发布为最终成绩。
- **证据与边界：** 本专项最初由权限迁移、生产路由、SQL claim、租约 middleware、任务 payload 和图片读取器静态确认。随后主控以真实 production router、全迁移、隔离 PostgreSQL 动态复现了平台 `page_processing_worker` 领取 demo 租户 `subjective-grading` 任务并获得有效租约，见 [`R01-worker-repro.md`](R01-worker-repro.md)；对象存储图片读取仍未动态重放。租约 token 仍由服务端生成，TaskScope 仍校验完整租约字段，未发现匿名绕过。跨租户领取的动态前提是平台 Worker 身份；普通租户 Worker 仅在本租户。影响前提始终是有效 `page_processing_worker` 凭据及待处理任务。
- **修复方向：** 由已认证身份服务端派生 Worker service 身份，并按身份限制可领取的 queue/task type；不要接受调用者自行声明的 Worker 名称作为授权依据。服务端 source result 和敏感输入路由应共同执行该绑定。

- **优先级：P2（集成门禁覆盖缺口）。** 未将其归类为生产行为缺陷。
- **位置：** [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml#L200) 行 200–213、276–318；[`e2e_auth_security_test.go`](../../services/api-gateway/internal/server/e2e_auth_security_test.go#L19) 行 19–24、196–201；[`e2e_postgres_test.go`](../../services/api-gateway/internal/server/e2e_postgres_test.go#L643) 行 643–653；[`e2e_math_rubric_score_test.go`](../../services/api-gateway/internal/server/e2e_math_rubric_score_test.go#L19) 行 19–37；[`scoring_handler.go`](../../services/api-gateway/internal/mathunderstanding/scoring_handler.go#L27) 行 27 起。
- **CI 触发方式：** `go-unit` 没设置 `EDUGRADE_E2E_DATABASE_URL`，这两个测试都会按自身前置条件 Skip。Postgres job 的 `-run` 是 `PostgresTestDatabase|PostgresMigrationUpgrade|PostgresManagedConfig|Story056.*E2E|Reliability.*Postgres`，不匹配 `TestTeacherAccountSecurityE2EWithPostgres` 或 `TestPostgresMathRubricScoreUsesOnlyFrozenExamRubric`，因此它们未进入该门禁。
- **独立执行证据与原因：** 提供的 `go-postgres-supplement.jsonl` 与 `go-postgres-failures-recheck.jsonl` 都记录了这两项失败。账户安全测试的 E2E router fixture 仅设置 `SessionTTL`，`RecentAuthTTL` 留空并回退默认 1 小时；测试把认证时间回拨 20 分钟后仍期待 428，因此收到 201。数学评分测试自建的最小 `answer_segment` 表未包含生产 Store 查询所需 `crop_sha256` 列，原始运行因此返回 500；仅补列后又因测试使用非 64 位十六进制的 crop hash 而返回 409，两个夹具问题均需修正。
- **非生产缺陷反证：** 提供的 [`fixture-diagnostic.log`](fixture-diagnostic.log) 记录了对诊断测试副本使用 Go overlay 的验证：将账户测试 TTL 改为 2 小时，并给数学测试夹具补 `crop_sha256`、换成合法 64 位 hash 后，两项均通过。overlay 没有修改业务源码。这支持“测试夹具／CI selector 与当前契约不同步”，不支持把这两条失败当成生产 handler 或 Store 缺陷。
- **修复方向：** 将两项测试纳入 PostgreSQL CI selector；让 E2E router 显式设置测试要覆盖的 `RecentAuthTTL`；数学测试夹具从现行迁移／生产列契约同步字段和有效 hash。
