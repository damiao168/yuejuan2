# S09 — SDK、共享类型、UI、OpenAPI 契约与共享命令恢复

审查基线：HEAD `84a33c572ab24f96f98d82426e101063cf4a1876`，包含当前工作区未提交修改。审查生成/手写 SDK 边界、共享 transport、OpenAPI 生成与主要命令恢复路径；对全量 API operation 未逐项人工核验。

## 发现

**本专项未确认可复现的契约或共享客户端缺陷。**

重点核验的路径参数由 `fillPath` 编码，数组 query 值按重复参数追加，错误 envelope 从 OpenAPI 的顶层 request/trace 与 field/conflict 字段和嵌套 error 字段取值；没有发现与当前契约不符的序列化行为。生成 API 客户端走同一个 `ApiTransport`，Web 与桌面 transport 的共享客户端 fixture 验证处理摘要和错误 request/trace/status 一致。管理端考试创建命令恢复在发请求前持久化不可变 payload、保留 idempotency key，未知结果先恢复回执再重放同一 payload，冲突不会静默换 key；已有单元与 integration fixture 覆盖这些关键转移。父级报告的 SDK/route coverage 生成只读比较为 MATCH，作为补充验证，不当作对所有业务契约的证明。
