## 这次具体解决什么

范围包括灰色辅助段落、字段下说明、页头导语、状态补充、提示条、Tooltip、禁用原因、空状态和成功反馈。部分长按钮、字段名或状态标签与小字重复表达同一事实，也一起处理。不会把题干、教师评语、学生申诉正文和用户输入当作可批量删改的产品文案。

每条方案至少回答：原文在哪里、什么状态会出现、用户是否需要它、删改后准确显示什么、在哪个条件与位置显示、需要改字还是改交互、哪些事实不能丢，以及如何验收。原文截取、动态模板与普通字面量分别标记，目标花括号是数据占位，不能直接上线为文字。

### 六类处置

| 处置 | 何时使用 | 具体落点 |
| --- | --- | --- |
| 删除 `delete` | 只复述字段、控件或另一段文字，没有新增事实 | “系统会保留结构化答案”；逐条重复的空意见段落 |
| 缩短 `shorten` | 信息有用，但混入实现过程或介绍界面的句子 | 公共电脑提示保留“最长4小时、离开前退出”，去掉“页面会持续提示” |
| 合并 `merge` | 同一事实在页头、状态标签、摘要和成功提示反复出现 | 发布成功消息只报结果；版本影响集中在发布结果区 |
| 按需展开 `progressive` | 少数用户需要的规则解释、专业诊断和历史记录 | 模板比较中的相同项、参考网址、算法细节 |
| 按条件显示 `contextual` | 只与当前题型、阶段、已选方案或异常有关 | 未生成二维码不讲二维码有效期；只解释当前锁住的编辑区 |
| 保留 `keep` | 用户必须凭它判断能否继续、后果是什么 | 未保存替换、正式发布、离线图片限制、身份与授权、数据范围和版本 |

一条可同时“缩短并保留”或“合并并按条件显示”。条目数代表处置决策数，包含保留示例，不等于待删除段落数。

## 显示规则

**同一事实在同一操作范围内默认只讲一次。** 页头说当前任务，字段旁说填写规则，按钮前说操作后果，结果区说已发生什么。用户从深链接进入时，该次决策必需的事实仍应可见，不能仅依赖“上次应该读过”。

| 信息 | 默认位置与时机 | 允许精简到什么程度 |
| --- | --- | --- |
| 数据作用域、非全量计数 | 摘要或结果列表旁，集中一次 | 可缩短，不能把当前已读取数改称全量总数 |
| 字段格式、范围、单位 | 字段标签或帮助，输入前可见 | 小数比例仍需明确单位；没有实现换算前不能直接改成百分比 |
| 仅某种方案适用的规则 | 选择对应方案后 | 非所选分支可隐藏；已有非默认历史值须能发现和核对 |
| 不可逆影响、冻结、替换、对外可见 | 相应动作前；必要的最终确认内 | 必须直说影响对象和内容，不能只留在Tooltip或帮助文档 |
| 阻止继续的原因 | 相关字段/动作附近，错误发生时 | 一句具体原因加真实可行的下一步；不统一退化为“刷新重试” |
| 查询中、提交中 | 正在处理的区域 | 短状态即可；不能把结果未知说成失败，不能暗示再次提交无风险 |
| 普通成功 | 原动作附近的短反馈 | 不再重复整段流程；需要用户继续交接时明确下一步 |
| 解释性背景、算法、原始ID | 有名称的详情/诊断入口 | 可折叠；专业管理员确实需要的证据完整保留 |
| 为空的可选材料 | 该内容区域 | 可省略重复“未提供”；缺失会阻断任务时必须显示原因和补齐入口 |

不要统一增加“了解更多”。帮助入口直接命名为“误差设置”“查看授权范围”“查看处理详情”等，用户能在打开前判断里面有什么。GOV.UK 的 [Details 指南](https://design-system.service.gov.uk/components/details/)建议把仅部分用户需要的信息放入展开区，并明确不应隐藏多数用户都需要的信息；这里据此区分解释性背景与操作前提。

## 文案写法与词语

优先写“发生了什么 + 需要时的下一步”。没有动作必要时只写事实，不强行加“请核实”“请确认”。不在每个输入框复述“请输入 + 标签”；示例只解释不直观的格式。标点、数字和单位使用一致形式，不为字数目标省掉业务主语。

| 原写法或含义 | 普通用户可见写法 | 保留条件 |
| --- | --- | --- |
| 已加载待阅卷 / 已加载已提交 | 待阅卷 / 已提交 | 范围说明在摘要处保留一次；计数失败显示缺失状态 |
| 单模型评分·非三智能体 | 单模型评分 | 架构对比留给专业配置详情 |
| Rubric | 评分细则 | 协议字段、版本证据、面向专业人员的原始字段名可保留 |
| 门禁 / 阻断 | 发布检查 / 暂不能发布 | 指明是哪项条件未满足，原检查代码保留在诊断详情 |
| 对象UUID、任务ID | 考试、题号、匿名答卷号等可读上下文 | 名称无权读取时保留可核对的受控标识，不额外扩大权限 |
| 未配置 / 未提供 | 依内容写“暂无参考答案”等，或省略可选空项 | 不把读取失败、无权限、未发布或被撤回都写成“暂无” |
| 本地修改已保留 | 你在本页的修改尚未被覆盖 | 没有持久恢复保证时，不写“已安全保存”“关闭后可恢复” |
| 已提交 / 已保存 / 已发布 | 各自保持独立含义 | 不把草稿已保存、正式发布和学生已能看到混为一谈 |
| 自动通知 / 自动续交 / 自动保存 | 仅实现和相关验证具备时使用 | 当前无此能力的方案，必须先完成对应交互或服务端改造 |

### 四个完整示例

**题库选择评分模板**

原来分两处解释“保存时复制评分点。模板后续更新不会更改本题。”及“选用模板将以该版本的评分点替换当前评分点；分值需一致。”目标是在选中模板后、保存之前只出现一次：

> 保存时用此模板替换本题评分细则（评分点、扣分规则和样例答案）；满分须一致。模板后续更新不影响本题。

未选模板时不提前显示替换警告。必须保留“保存时”的时机，不能让用户误以为选择后已经修改完成。模板替换整个评分细则，不替换本题的标准答案和解析。详见 MC-R21。

**题库两个编辑区互锁**

原来：“请先保存当前编辑区域，再编辑另一部分或提交审核。”目标按实际修改区显示：

> 先保存题目内容，再编辑评分标准或提交审核。

如果改的是评分区，则显示“先保存评分标准，再编辑题目内容或提交审核”。这只能改善理解；两个编辑区分别保存的流程问题仍由综合审计的统一保存方案处理。详见 MC-R12。

**教师任务摘要**

标签改为“待阅卷 / 待仲裁 / 已提交”，统一说明：

> 摘要仅统计当前已读取任务。完整任务请进入阅卷或仲裁列表。

读取失败的类别仍显示“—”和失败提示；不能只删“已加载”后把局部数量伪装成全场总数。详见 MC-R01、MC-R02。

**公共电脑登录**

原来：“公共电脑会话最长 4 小时；页面会持续提示，离开前请点退出。”改为：

> 公共电脑登录最长 4 小时，离开前请退出。

只在用户选择公共电脑策略后出现，不缩成没有约束的“注意账号安全”。详见 MC-R04。

## 排版与可访问性

减少文字依靠删重复、调整层次和显示条件。**保留下来的信息不再缩小、调浅、截断成不可读的小字。** 当前共享caption为0.8125rem，大字模式为0.875rem；本轮不建议仅为容纳长说明继续缩小字号。关键操作后果应提升到正文层级、靠近动作，而不是全站把所有辅助字改成警告。

- 正文和正常辅助文字按实际前景/背景验证至少4.5:1对比度；字号较小本身不能据此断定违规，也不能假定所有灰字都不合格。阈值依据 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。本轮未对运行界面逐处测量，不能声明全站已经通过。
- 保留字段label；格式、单位和错误与控件建立可访问关联，不能全部塞进占位符。依据 [W3C 表单说明](https://www.w3.org/WAI/tutorials/forms/instructions/)。
- 展开帮助使用真实button或details/summary，键盘可操作、展开状态可感知。触屏必须有点开方式，不依赖悬浮。
- 必须保留的Tooltip需符合可关闭、指针可移入、内容持续可读的要求，见 [W3C Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)。阻断原因和危险后果直接显示，不仅在Tooltip中提供。
- 验证常规与大字模式、桌面宽屏与390px窄屏、浏览器200%缩放。长的必要说明允许换行，不靠省略号截去单位、版本或后果；此处是待实施验收条件，未宣称已运行通过。

## 实施顺序

### 第一批：保持行为的文案与去重

先做清单中 `dependency=copy` 的条目，逐条核对 `keep` 边界；它们不应引入新接口、自动保存、通知或状态迁移。优先处理含糊的提交结果、公共电脑时限、离线限制与密码恢复联系路径，再处理实现术语和冗长成功提示。`keep` 条目用于说明不改动的理由，不是要求制造一次代码修改。

验收以原状态下文字含义准确、按钮和权限一致为准。涉及既有文案测试或快照时同步更新相应断言，但不为纯措辞增加镜像实现测试。

### 第二批：条件显示与集中说明

再做 `frontend` 条目：按当前方案/题型/状态显示说明、合并重复状态、折叠相同比较项和完整参考地址、把阻断原因移近动作。这里必须测条件分支，不能只全局替换字符串。

重点依赖：MC-R02先区分空数据与失败；MC-R07与MC-R10配套保留考试版本影响；MC-R22先修复综合审计F01的语义空值假差异再计算差异数量。未经实现和验证，不得提前上线“有N项不同”等会依赖新逻辑的文案。

### 第三批：衔接流程整改

本轮条目没有要求直接修改后端；自动化、通知、统一保存、报告导入等能力仍按综合审计安排。若后续要删除当前服务端仍强制要求的输入字段，必须同步调整规则、契约和流程；仅隐藏小字或输入控件，会让用户直到提交才遇到拒绝。例如MC-G02继续准确说明当前双模型两个阈值都必填，不把另一个流程整改提前写成已支持。

### 每批交付检查

1. 原文与当前源码重新核对；如果行号、显示条件或规则已改变，先更新条目和证据。
2. 一条提示只有一个明确职责；同一事实没有在相邻多个区域重复。
3. 必填、权限、冻结、提交/保存/发布差异、数据范围、结果未知、离线与撤回限制没有被淡化。
4. 正常、为空、读取失败、无权限、历史值、未保存、冲突等相关分支与具体条目的验收一致。
5. 执行涉及模块现有的文案检查和必要测试；界面变化验证键盘、触屏、大字与窄屏。
6. 按逐文件状态记录实际实施、保留或未处理；本轮的 `proposal_not_implemented` 不能批量改成已完成。

## 覆盖与证据边界

当前目录会枚举应用与共享UI相关源码，记录辅助文字标记的候选位置，帮助后续发现遗漏。候选搜索不是正文审读，不是运行验证。只有本轮明确全文读过的文件标记 `reviewed`；片段保持 `partial`，未读文件保持 `pending`。所有条目的源文件哈希写入覆盖清单，原文与行号另行校验。

本轮复核以静态源码和上一轮已说明范围的合成浏览器证据为依据，没有重新跑完真实账号、真实阅卷、离线硬件或所有权限分支，也没有进行教师/学生可用性实验。不以“全仓搜索”声称找齐所有动态文案，不给未经测量的文字减少百分比或操作耗时提升。
