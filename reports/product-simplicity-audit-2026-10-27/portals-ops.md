## 建议优先处理

1. 日常学生导入接受学校现有中文表头，复用初始化已有的列映射；增加 Excel 导入。
2. 把桌面扫描改为“选考试和批次 → 核对自动读取的模板 → 导入上传 → 统一处理进度”，合并分散刷新。
3. 学生查看答案时只展示作答与反馈，点击“申请复核”后才展开申请表和圈选工具。
4. 离线评分按评分点自动汇总总分，例外才要求解释总分调整。
5. 治理页支持导入已有评测报告并核对，减少哈希、版本和指标的手工抄录。

## 学生端

### S01 / P2：每次查分都要求理解并输入学校代码

- 场景：学生从学校分享的入口打开查分页面。
- 依据：`apps/student-portal/src/features/session/SessionScreens.tsx:7` 每次登录组件初始化学校代码为空；35–37 行并列要求学校代码、账号、密码；41 行把忘记代码也交给管理员解决。
- 负担：学校上下文没有体现在登录入口里，学生多记一项管理员分配的信息。这里的学校代码用于租户定位，有必要存在于系统中。
- 建议：学校专属查分链接预填学校代码并显示学校名称；普通入口保留“切换学校”。不要移除服务端租户验证。
- 验证边界：需实机检查学校实际发放链接是否已有外部跳转机制；本组件没有该预填逻辑。

### S02 / P2：最近一场考试在首页展示两遍

- 依据：`apps/student-portal/src/features/results/ExamList.tsx:56–60` 展示 `items[0]` 的完整最近发布区；61–65 行再次遍历全部 items，包括同一场考试。两个入口分别称“查看考试分析”和“查看成绩”，都调用同一个 `onOpen`。
- 负担：列表少时页面重复，两个文案暗示不同目的，实际进入同一详情。
- 建议：保留最近考试的大入口，将后续列表改为“其他考试”；同一目的统一称“查看成绩与分析”。

### S03 / P1：只是查看答案，也会自动展开整张复核申请表

- 依据：`apps/student-portal/src/features/questions/QuestionTables.tsx:266–267` 在加载答案后，只要复核窗口开放就直接挂载 `QuestionAppealForm`，不要求用户先选择申请；同文件47行已经另设“申请本题复核”。
- 复核：`QuestionAppealForm.tsx:179–199` 直接渲染标题、图片圈选、原因、说明和提交按钮；并非仅挂一个收起容器。
- 负担：看作答这一高频任务被申请说明、原因选择、长文本和图像圈选这一低频任务占据。用户无须申请也要看到整个表单。
- 建议：详情默认展示答案和评分；保留一个“申请本题复核”按钮，主动点击后再展开表单并聚焦理由。已有申请则直接显示简短状态。

### S04 / P2：申请复核重复显示答卷，并暴露几何编辑器

- 依据：`apps/student-portal/src/features/questions/AnswerReview.tsx:17–31` 已展示本题原卷；`apps/student-portal/src/features/appeals/QuestionAppealForm.tsx:187–192` 随后再次展示同一题图片；246–268 行提供拖动框选、两点模式开关和整图选择。选中区域后才会出现默认折叠的“精确调整区域（百分比）”，四项坐标输入没有常驻展示。
- 负担：同一张答题图反复占空间；本来可选的圈选工具跟随申请表自动出现，打断单纯看作答的任务。本条不将已折叠的百分比输入视为首屏负担。
- 建议：默认只填原因；“标记争议位置”展开后复用上方答卷图。保留两点辅助交互与现有精确调整折叠区。

### S05 / P2：逐题列表把统计分析放得和个人得分一样重

- 依据：`apps/student-portal/src/features/questions/QuestionTables.tsx:221` 默认七列含正确答案、实际答案、得分、班级均分、参试均分、中位分对比；55–56 行两列重复挂载同一个 `QuestionCohortScope`。`QuestionCohortScope.tsx:8` 的“本版考试本题 · 参比N人”因而每行出现两遍。
- 负担：学生找“哪题失分”需要横向辨认大量次要统计；同一参比说明重复。
- 建议：默认突出题号、我的得分、失分、查看作答；将均分与中位数放入“比较数据”开关或题目详情。参比说明按统计范围集中显示，差异题目才单独说明。

### S06 / P2：成绩与复核记录各自刷新，学生需要区分两套新旧状态

- 依据：`apps/student-portal/src/features/results/ResultDetail.tsx:89–92` 有“检查最新成绩”及“查看新版成绩”；`apps/student-portal/src/features/appeals/AppealStatus.tsx:56–70,85–86` 又独立读取当前成绩，并有另一“刷新”按钮及“当前生效成绩暂未核实”的状态。
- 负担：学生可能刚更新成绩，又面对复核区仍需刷新确认的信息。技术上的多个请求变成用户的多套刷新动作。
- 建议：页面统一一个“更新成绩与复核进度”动作，内部协调请求；每条申请保持原申请版本与当前结果的准确对应。不能用版本号大小推断复核已生效。

### S07 / P2：一张复核记录反复解释同一处理状态

- 依据：`apps/student-portal/src/features/appeals/AppealStatus.tsx:89–98` 同时显示原因、原版本/原分、复核前后分、状态文字、处理结论、生效版本说明、当前本题分和右侧同名状态标签；108 行的生效说明还可再次包含当前本题分。
- 负担：学生最关心“处理完了吗、改了多少、老师怎么回复”，却要拼读多段接近审计说明的句子。
- 建议：首行保留“处理中/已完成”和分数变化，接学校回复；把申请时间、原发布版本、关联发布等放到“处理详情”。版本证据仍完整保留。

## 桌面工作站

### D01 / P2：连接与登录拆成多项管理动作

- 依据：`apps/desktop-client/src/App.tsx:326–337` 文案要求先检查并保存地址，提供“保存服务器地址”“检查连接”；随后另填学校代码、账号、密码（347–354）；登录成功再点击“查看我的任务/导入答卷”（381）。`features/session/useDesktopSession.ts:139–142` 的登录已经传入当前服务器地址。
- 负担：第一次使用要理解“保存”和“检查”是否是登录前置步骤，成功后还需主动跳转。
- 建议：学校预配置服务器与学校代码；普通用户一个“连接并登录”，失败时再展开连接诊断；成功回到上次任务或工作台。高级设置保留换服务器。
- 验证边界：保存/检测不是这里代码强制的登录前置，问题是界面引导与额外入口。

### D02 / P2：同一任务列表在两页重复，打开任务又分成三个动作

- 依据：`apps/desktop-client/src/App.tsx:401–436` 有单独任务页及“开始阅卷”；`components/offlineWorkbench/OfflineWorkbenchView.tsx:56–58` 每行同时有“选择”和“打开阅卷”，268–271 行又显示同一任务列表和“下载任务包”按钮。
- 负担：用户需判断是选中、下载还是打开；从任务页进入后又看到另一份任务选择器。
- 建议：统一“开始/继续阅卷”入口，自动加载已保存草稿或下载所需材料。工作台只保留紧凑切题列表；重新下载作为异常恢复动作。

### D03 / P1：扫描工作流的视觉顺序与依赖顺序相反

- 依据：`apps/desktop-client/src/features/scan/ScanWorkspace.tsx:58–64` 先渲染模板参数、设备控制，再渲染考试/批次；119 行明确告诉用户“请先在下方选择考试和采集批次”。
- 负担：刚进入先遇到“模板尚未确认”和纸张/DPI选择，真正第一步却在后面。
- 建议：把考试和批次放到第一行；选定后显示读取的模板摘要，再显示文件导入。纸张/DPI放在“检查参数”，必要时再核对。

### D04 / P1：用户承担多套刷新和检查的编排工作

- 依据：`apps/desktop-client/src/features/scan/ScanWorkspace.tsx:62–63` 考试和批次各有刷新，86 行“重新读取考试与批次名称”，92–103 行还有页数完整性检查、处理结果刷新、选择已关联答卷、图像质量刷新；120 行另有“重新读取模板”。
- 负担：上传后要知道下一步检查哪个接口、何时换哪个答卷，才能判断是否完成。
- 建议：集中“更新当前批次进度”，在上传和选择批次后自动更新相关状态；明确显示“已收件→匹配→页数→图像质量”的结果，只给失败步骤对应修复入口。后台页数检查与图像质量仍分别判定。

### D05 / P2：未启用直接采集，却把设备档案设置放在导入主流程

- 依据：`apps/desktop-client/src/features/scan/ScanWorkspace.tsx:147` 明确“当前直接采集尚未启用”，但148–168行仍常驻扫描设备档案、双面、运行设备检查、新建档案、刷新档案，且排在导入文件前。
- 负担：只想导入现有 PDF 的扫描员误以为必须先配置设备；不可直接扫描的功能带来完整设置负担。
- 建议：现有文件导入作为默认入口；设备检查收进“设备诊断（可选）”。直接采集能力启用后再建立单独的“从扫描仪采集”模式。

### D06 / P1：离线保存不包含答卷图片，重启后核心任务又依赖联网

- 依据：`apps/desktop-client/src/components/offlineWorkbench/OfflineWorkbenchView.tsx:237–239` 明确图片仅本次会话缓存、重启后需要联网恢复；273–274行有“恢复答卷图片”。`App.tsx:447,451` 还要求启用离线授权、加密保存，并说明图像仍需在线恢复。进一步核实 `useOfflineWorkbench.tsx:279–286` 保存的是任务包快照与草稿，342–347行明确解密草稿不包含图片并清空 `imagePreview`；`taskPackage.ts:70–82` 任务包只记录图像URL。这条路径由原生端与浏览器共用，并非只在浏览器开发模式有此限制。
- 负担：用户完成授权与保存后，以为已备好离线任务，重启后仍可能无法核对手写作答。现有说明准确，但任务模型本身要求用户理解数种不同的保存状态。
- 建议：提供可核对的“准备离线任务”动作，将获授权的答卷、题目和评分细则一起加密缓存，显示完整性结果及有效期；若当前实现只能保存文字，界面明确称“离线评分草稿”，在离线准备前告知材料限制。
- 验证边界：这是源码明确声明的能力边界，不声称所有任务都不可离线；有可读答卷文字的任务仍可核对。

### D07 / P1：评分点不联动总分，按点评分后仍要人工汇总

- 依据：`apps/desktop-client/src/components/offlineWorkbench/OfflineWorkbenchView.tsx:161–181` 总分与每个评分点分别编辑，改评分点只改 `rubricSelections`；194–195 行有差异原因输入。`useOfflineWorkbench.tsx:439–441` 总分与评分点不等时要求原因。
- 负担：正常按点给分也需再算一遍总分；遗漏汇总就触发“人工调整原因”。
- 限定：并非每个评分点都被表单强制必填；也可以只改总分并解释差异。问题是常见的逐点评分路径缺少自动汇总。
- 建议：正常路径自动汇总评分点为总分；教师主动选择“调整总分”时才解锁总分及必填原因。保留人工覆盖和差异审计。

### D08 / P2：多种评语输入常驻，用户难分内容该写在哪里

- 依据：`apps/desktop-client/src/components/offlineWorkbench/OfflineWorkbenchView.tsx:185–195` 连续显示教师评语、学生可见反馈、内部备注、人工调整/提交原因四项；“教师评语”和“内部备注”语义尤其接近。
- 负担：给一题评分需先理解四种数据去向，即使都可选也占据编辑区域。
- 建议：默认保留“给学生的反馈”；内部记录折叠为一处，保留不同权限下的存储字段；只有调整触发原因要求时才展示原因栏。

### D09 / P2：生产端仍用开发模式的“已输入离线密钥”状态

- 依据：`apps/desktop-client/src/components/offlineWorkbench/OfflineWorkbenchView.tsx:19–23` 用 hasKey 显示“离线密钥已输入”；244 行只有浏览器开发模式才显示密钥输入框。`useOfflineWorkbench.tsx:54` 的 hasKey 在原生存储可用时直接为 true。
- 负担：原生用户没输入密钥也看到“已输入”，会误以为存在另一项应记住的密码。与“本机授权/Windows凭据库”等状态混在一起。
- 建议：原生端显示“本机加密存储可用”，开发模式才使用“开发密钥已输入”；用户界面只突出是否可以保存和离线继续。

### D10 / P2：PDF能进入预览，纯PDF材料却不能完成阅卷

- 场景限定：任务上下文提供 PDF 作答材料且没有可读答卷文字；不声称真实任务接口通常或必然返回这种材料。
- 依据：`apps/desktop-client/src/components/AnswerDocumentViewer.tsx:76–77` 用 iframe 展示 PDF；54–55 行把 PDF 排除在可读回执之外。`components/offlineWorkbench/useOfflineWorkbench.tsx:58–60,430–434` 只接受答卷文字或成功解码图片作为可核对材料。因此仅 PDF 的任务即使阅读器显示正常，同步提交仍被阻止。
- 负担：教师已阅读原件，却要离开当前流程联系负责人补一份其他格式材料；单纯重试下载不能解决格式限制。
- 建议：服务端或受控查看器把获授权 PDF 转为可验证解码的逐页图片，保留原件下载。若暂不支持，进入任务时就给出“需转换PDF材料”的明确下一步，避免教师先评分再在提交时遇阻。
- 边界：不能把 iframe 的 onLoad 直接当作内容可读，也不建议绕过材料校验。

## 学校与平台管理

### O03 / P1：日常名单导入比首次初始化更难用

- 依据：`apps/web-admin/src/pages/StudentManagementPage.tsx:347–350` 只接收 CSV；`features/members/students/studentImport.ts:35–42` 强制英文 student_no/name/class_code，报错直接暴露字段名。与 `pages/OrganizationSetupPage.tsx:235–239,299–302` 已支持中文表头自动识别与列映射不同。

### O04 / P1：操作记录有三层找数据方式和两层翻页
