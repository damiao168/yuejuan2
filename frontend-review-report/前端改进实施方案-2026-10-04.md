## 2. 对报告 27 条建议的逐项采纳决定

本文优先级：P1 为近期应安排的正确性、交互和高收益治理；P2 为渐进维护；有产品触发条件的项目按条件启动。出现实际越权、草稿丢失或生产不可用时，再将对应缺陷升级为 P0。

**明确不采纳的部分：**

- 不接受没有基准数据支持的“高于行业平均水平”和综合评分作为工程决策依据。
- 不把路由职责重叠和手写业务队列直接定为 P0；不因 Query 使用文件少就迁移所有状态。
- 不删除草稿串行/修订队列、租约状态机和失败恢复机制来换取形式上的库统一。
- 不强制所有组件 250–300 行，不按 props 个数引入 Context，不全量补 memo。
- 不强制合并 ConfigProvider，不以 TSX import 次数否定 CSS tokens 使用，不将所有同色或同名组件强行统一。
- 不因全局 CSS 数量就全仓迁移，不消除图像几何所需的动态内联值，不手写哈希 modulepreload。
- 不把相邻 feature 目录没有测试文件解释为业务没有测试，不立即设一刀切覆盖率。
- 不接受“SDK 契约完整”的前提，不把服务端 route coverage 当作前端 SDK 使用率。
- 不重复建立现有 Node/audit/CI 基建，不为了空目录补建教师端或填充 auth-client。

路由全量迁移、AuthProvider、工作台 controller/Context、共享 transport 和大范围样式改造均不是首批必须完成项。只在试点证明减少重复维护、保证现有行为且迁移成本可控后扩大；若没有明显收益，保留当前实现并完善维护边界即可。

## 4. 会话与命令作用域：先处理顺序，再抽 AuthProvider

`AppShell.tsx` 的渲染体调用 `setBusinessCommandScope` 确实应移除。React 要求渲染阶段保持纯净，副作用放入事件或 Effect；但具体落点必须满足业务时序。[React 渲染纯净规则](https://react.dev/reference/rules/components-and-hooks-must-be-pure)

这里的 scope 不是普通 UI 属性。`businessCommand.ts` 用模块全局 scope 构造 `business-command:tenant:actor:operation:target` 的持久化键。当前核查到的执行入口主要由用户动作触发，尚未证实子页面 Effect 已造成串账号命令。简单移到父组件 useEffect 只修渲染纯度，仍留下全局 scope 的时序隐患；需验证会话绑定先于首个命令的规则，不能把潜在场景描述为已发生事故。

实施方案：

1. 增加统一的会话提交函数。恢复和登录结果先核对请求代次，拒绝过期结果；同步绑定命令身份，再发布已登录 user，使子页面只在身份就绪后挂载。
2. 退出先停止接受新命令，清空当前作用域，取消旧 Query 请求，再清缓存和账号数据。已发出的远端命令不因本地取消就被认定为撤销；保留它的原命令 ID 和查询回执所需事实。
3. 清理公共电脑数据、草稿 fallback、锁屏和二次认证仍按现有边界执行。普通退出与公共电脑离开清理不能机械合并。
4. 中期让命令执行器持有不可变会话 scope，或通过服务上下文显式注入；回调只使用发起时的身份，而不是再次读取可变模块全局值。scope 键采用结构化/编码规则，并规划旧持久化键兼容。
5. 路由试点或多处复用确实需要时，再抽 AuthProvider/useAuth，负责恢复、登录、退出、锁屏和会话失效。激活/恢复保留真实 pathname、token、租户参数；Onboarding 独立处理业务启用状态，不混入所有身份认证逻辑。

捕获 scope 不能固定浏览器 Cookie 的网络身份。命令恢复存在“查询回执→等待→后续写入”的间隔，每次 fetch 使用当时的 Cookie。执行器还须捕获会话代次，在每次 await 后、准备新的网络写请求前再次核对；退出/切身份立即使旧执行器失效。已发出的请求只能按其结果与回执处理，不能承诺本地取消会撤回服务端提交。

必须新增/复用的验收：恢复晚于退出、快速登录 A/B、旧请求晚到、命令响应丢失后恢复、StepUp 取消/失败、公共电脑锁屏、旧账号请求不能删除新账号缓存或更新界面。持久化幂等键和冻结载荷保持一致。前端检查仍不能代替服务端授权。

## 5. 首屏性能：先改明确的依赖来源

### 5.1 现有构建线索

本次读取 2026-10-04 已存在的 Web dist，并用 Node zlib 计算 gzip；这些不是本次重新构建的当前发布基线，也不是 HTTP 实际传输量。

| 产物 | 原始大小，约 KiB | 本地 gzip，约 KiB |
| --- | ---: | ---: |
| 入口 index JS | 1,507 | 450 |
| antd chunk | 1,172 | 365 |
| motion chunk | 126 | 42 |
| 入口 CSS | 298 | 53 |
| charts chunk | 382 | 105 |
| PDF worker | 1,015 | 281 |

构建 HTML 直接引用入口并 modulepreload antd/motion，三份 JS 的 gzip 合计约 856 KiB。图表和 PDF worker 的总大小不能直接相加称为“首屏下载”，还需网络瀑布验证实际加载时机。

当前源码静态导入链有明确证据：

```text
main → App → appRouter → AppShell → SchoolAssistantProvider
  → SchoolConversation → conversationAttachments → pdfjs-dist
  → SchoolConversationDisplay → MathMarkdown → rehype-katex
```

`drawerOpen && <SchoolConversation />` 只延后渲染，不会切断静态 import。这是优先处理点。页面本身已有 lazy，仍可能被全局 Provider 重新带回首屏依赖。

### 5.2 改造步骤

1. SchoolAssistantProvider 保留轻量权限、账号 scope 和开关状态；对话 UI 用模块顶层 lazy 导入，Suspense 和加载失败处理只包抽屉内容，不能让整个后台进入 loading。
2. PDF 解析在用户实际上传 PDF 时再动态加载，包括 worker 配置；图片/文本上传不加载 PDF。维持上传限制、错误文案、关闭/切账号时的取消和迟到结果隔离。
3. MathMarkdown 优先随对话/资料页面分割。不能为了体积把公式变成错误纯文本，也不能移除已有 HTML/公式信任边界。
4. 对比当前 manualChunks、自动分块和按功能重依赖分块三种产物。选择依据是登录、管理员首页、教师首页、阅卷、PDF 上传五个场景的传输量、解析执行和缓存命中，不预设“antd 越碎越好”。
5. 构建输出 manifest 和模块体积清单；可使用适配当前 Vite/Rollup 的可视化工具辅助定位，统计脚本同时记录 raw/gzip、入口静态依赖和路由增量。分析报告保留为 CI 产物。
6. 加静态加载占位及 noscript。保持 CSP，避免新增内联脚本；沿用构建器已有 preload，绝不手填产物 hash。服务压缩与缓存策略另测，不能把 gzip 估算当生产已启用压缩。

验收：登录和未打开助手的页面没有学校对话带来的 PDF/公式模块执行；首次打开助手和首次上传 PDF 各有可理解的等待/失败状态；关闭抽屉或换身份不显示旧结果。新构建与同环境基线比较，首屏依赖明显减少，核心操作不退化。预算先按实测基线设“增长 5% 提醒、10% 阻断”的候选值，校准后再固化；这些比例是治理起点，不是通用性能标准。

## 6. 路由：保留 TanStack，分路由族收敛

当前是 TanStack 根路由挂 AppShell，叶子路由较少，AppShell 使用业务注册表完成真实页面选择；不是两个 Router 争抢 history。保留已投入的 TanStack，比再扩展一套路由内核更合适，但本期不因 URL 美观换 Hash history。

目标职责：

| 模块 | 目标责任 |
| --- | --- |
| 路由树 | URL 匹配、参数、布局、页面 component、页面级加载/异常 |
| 路由注册表 | key、标题、导航分组、生产可见性、体验和访问策略元数据 |
| 共享访问函数 | 菜单与深链使用同一规则，避免两份权限逻辑漂移 |
| AuthProvider | 会话与认证生命周期，通过 router context 提供身份 |
| 工作台业务层 | 认领、续租、草稿、提交、离开保护 |

试点与条件扩展步骤：

1. 先固化现有 URL 和行为：体验前缀、旧链接重定向、query、URI 编码、403/404、归档只读、生产 mock 排除。
2. 用首页、账号和考试列表等 3–5 个只读入口做试点，设置真实 component 和布局出口；参数解析逐步迁移为受校验的路由参数。试点验证通过后每批迁移一个路由族。
3. beforeLoad 做身份/体验/访问检查，角色决定可进入的体验，权限决定业务动作；双角色用户在 teacher 体验仍不显示管理操作。路由预加载会涉及加载流程，认领/续租等业务写入不放 beforeLoad/loader。[TanStack 认证路由文档](https://tanstack.com/router/latest/docs/guide/authenticated-routes)
4. 接入 AuthProvider 后，会话变化同步更新 router context 并使访问判断重新执行；未经确认不能复用旧权限上下文。
5. 保留 push、后退、前进及浏览器离开的未保存保护。busy 禁止离开、dirty 确认；工作台按账号/考试重建的 key 继续保持，布局迁移不能重挂载正在编辑的草稿。
6. 只有试点证明真实减少 URL/页面分发重复、权限规则仍单一且迁移成本可控，才继续阅卷、仲裁、采集等交互页。条件不成立时保留现有架构，说明各层职责并维护测试即可。全量迁移确实完成后再移除大 switch 和通配兼容兜底，只保留明确旧链接兼容路由。

验收：教师深链管理页返回 403；双角色 teacher 体验不能绕过限制；管理员与教师阅卷入口正确；教师不请求原始整图；dirty/busy 状态下各种离开方式一致；刷新深链、旧链接和未知路径正确；生产构建无 mock 页注册。权限保证最终由服务端执行。

## 7. 工作台：先统一缓存依赖，再迁任务分页

### 7.1 Query 与业务状态的边界

| 数据/机制 | 处理策略 |
| --- | --- |
| 阅卷员、完整任务聚合 | 可做 Query 试点，显式按身份、考试和队列范围隔离；收益不足时保留现有读取 |
| 任务上下文 | 已部分 Query 化；统一 queryOptions 与 client，区分原图/当前人草稿等权限作用域 |
| 游标任务列表 | 有可证明收益时最后试点 useInfiniteQuery；保留全部页加载、去重、锚点及 revision 合并 |
| 下一两题和图片预取 | 复用上下文 Query；一次性 bundle 消费与 Blob URL 资源释放仍由业务层管理 |
| 当前编辑草稿 | 本地编辑状态；后台刷新不能覆盖未保存输入 |
| 串行草稿队列 | 保留账号+任务串行和 expected_revision 顺序 |
| 认领、续租、提交、转派、冲突 | 明确动作和状态转换；不作为普通查询自动重试 |

TanStack Query 的后台刷新与重试需要按业务配置，不能靠库默认值推断安全性。本项目已有 30 秒 staleTime、关闭窗口焦点刷新、限制读重试及写 retry:false；迁移时保留有意配置，并对 reconnect 等入口逐项确认。[Query 默认行为文档](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)

### 7.2 一项近期治理与三项条件试点

近期优先处理 client 依赖一致性、账号作用域和迟到请求测试。以下 B/C/D 都不是为了统一库而必须执行：先选最小范围验证，只有减少重复请求/缓存职责或明显降低修改耦合、且所有时序回归保持时才扩大，否则保留现有 hook、队列和 controller。

**A：依赖注入与账号 scope。** 顶层/hook 用 useQueryClient，纯 helper 显式接收 client 或服务。`GradingWorkbench`、`gradingTaskContext`、`workbenchDraftLifecycle` 和 `useGradingReviewActions` 同批调整；不能只换顶层而 helper 仍读另一个单例。query key 按实际影响响应的会话代次、tenant/user、exam/task、队列及原图权限范围隔离，相应 invalidation、prefetch、remove 同步更新；不把 token 等凭据放进 key。

重点回归一个风险：旧账号草稿保存晚到时，生命周期内的 removeQueries 目前不能仅靠 UI generation guard 被视为账号隔离。应测试旧响应只触及原 scope，不能删新会话缓存；这是待验证的缓存失效风险，尚不是已证实数据泄露。

**B：只读数据试点。** 选阅卷员或完整 aggregate 一项试点 Query；上下文沿用现有 queryOptions。aggregate 使用服务端完整结果，不能把每页 aggregate 相加。取消信号接到 transport，网络结果提交仍核对发起 scope，取消请求本身不构成完整隔离保证。

**C：草稿 controller 条件拆分。** 现有生命周期模块仍难以独立测试或区域耦合明确时，才抽 useWorkbenchDraftSession，集中草稿加载、1200ms 防抖、同账号换题 flush、冲突和 fallback。可用小 reducer 表达 hydrating/editing/saving/conflicted/offline，timer/网络/队列仍留在服务或 effect。draft、draftRevision、lastSavedDraft 和 live ref 的职责不同，不能机械合并。

**D：任务分页条件试点。** 后端 ListTasks GET 是查询，但列表中的任务携带租约、版本与分配事实。若确认通用分页/缓存重复维护是实际成本，再试点 useInfiniteQuery，保留游标去重、刷新代次、未拉全不回绕、提交后下一题锚点、转派范围及旧页 revision 不覆盖新事实的规则。本地 keyword/filter 不在接口未支持时搬到服务器参数。

写路径可继续现有服务。若后续使用 useMutation，只封装请求状态并保留业务队列与幂等恢复；串行 mutation 并不自动获得“跳过过期快照、正确递增 revision、失败保留 fallback”的语义。[Mutation 文档](https://tanstack.com/query/latest/docs/framework/react/guides/mutations)

验收必须包含：A 慢/B 快的上下文切换；保存/提交中换题或换账号；同任务两快照串行 revision 正确；旧成功不删新 fallback；旧 409 只影响原任务；断网/响应丢失不无限重试写；120 任务按 50/50/20 页无重复遗漏；游标不前进停止循环；转派后范围和完整进度同步；盲质检不续租不保存；脏草稿不被刷新覆盖；权限缩小后原图模式降级。现有 mock E2E 只能证明前端交互，真实数据库租约需要单独集成验证。

## 10. SDK 与跨端 transport：分两条线推进

**契约线。** 建端点清单：method/path、前端消费者、OpenAPI operationId、生成/手写、认证、请求/响应类型、状态码、分页、revision、幂等、SSE/Blob/multipart。优先稳定公开读和高频写，内部 worker/运维接口依既有例外政策处理，不为覆盖比例强行对外公开。

补 OpenAPI 权威源，包括错误、header 和版本规则，再执行生成及已有契约门禁。手写的跨端点聚合、冻结命令和恢复编排可保留，只替换底层端点调用。review/capture 当前已有混合使用，不应整文件重写。已存在 route debt budget 和精确写接口缺口门禁，继续减少债务，新增“前端消费端点”指标即可；服务端 route coverage 无法自动代表前端生成调用率。

验收：生成调用替换保持实际 method/path/body/header/status 行为兼容；原文档有误时依据 handler 与批准契约纠正，不保留错误 schema。CSRF、Idempotency-Key、revision 和 command recovery 保留；生成一致性、破坏性变更、授权和 schema 门禁通过；生产契约样例和对应 UI 失败场景正确。生成目录不得手改。

**复用线。** SDK runtime 已有 ApiTransport 与错误归一化。先抽公共错误结构、code 映射和 JSON/204/FormData/文件名解析等纯逻辑，再视实际重复扩 transport，不先造大而空的 core 包。

| Web 保留的政策 | Desktop 保留的政策 |
| --- | --- |
| cookie credentials、CSRF、428 StepUp 事件、Retry-After、SSE、下载水印等 | HTTPS/loopback 地址校验、Bearer token、服务器绑定、durableScopeKey、IPC 和加密离线存储 |

公共层可注入 fetch、凭据策略、header 和认证事件回调；Tauri IPC 与持久化队列不进入通用 transport。跨端统一 ApiClientError 时检查 `instanceof` 和旧导出兼容，防止 Query retry/错误展示行为改变。服务端原始 message 不直接回显。写请求不默认自动重试，业务恢复仍复用冻结操作 ID。

验收：共用协议测试分别通过 cookie 与 Bearer 两种配置；各端既有 client/userError 测试继续通过；204、JSON/非 JSON 错误、FormData、Blob、428、401、超时/取消正确；desktop security config 和离线恢复不退化。

**独立待验证项：桌面阅卷响应丢失。** `desktop-client/api/review.ts` 提交未传持久化固定幂等键，client 在缺键时每次生成新键；OfflineWorkbench 已在网络前加密保存草稿，并有 revision 冲突和内存确认保护，但不能据此认定跨重启后能确认一次丢失响应的原成功结果。应先复现“服务端已成功→响应丢失→进程重启→恢复同步”，判断是否进入无法对账的冲突状态；目前不宣称重复评分漏洞。

复现成立后独立安排 P1 修复：在 durable 草稿中冻结 command ID/幂等键及完整载荷，恢复时复用已批准的评分命令/回执契约，先确认回执再决定是否重发；缺契约时补权威服务端支持。保护 expected_revision，并覆盖远端成功、本地状态写失败和切服务器/账号场景。该修复涉及业务持久化，不能藏在 transport 共享批次中。

## 11. 测试与可访问性：补业务缺口

先建立“规则→实现→单测→E2E/集成→缺口”矩阵，覆盖率基线后置。现无统一前端 coverage provider/threshold，目录文件数不是覆盖率；暂不设所有 feature 80%/90% 的一刀切目标。

重点校准补测：阈值等于边界；缺配置不错误拦截；已配置 criterion 但 metric 缺失不能通过；提交前隐藏参考分；保存 policy revision；关闭/换题后的迟到响应。CalibrationDrawer 的请求代次保护需独立复现核查，目前不能仅凭代码抽样宣称已有缺陷。

1. 快捷键帮助加单字符快捷键开关，或限定到明确工作台焦点作用域；保留输入法、repeat、输入框、弹层和权限 guard，处理 defaultPrevented，尊重浏览器 Ctrl/⌘ 组合键。
2. 查看区可聚焦并命名，局部方向键平移、归位/适配，必要时 Shift 加速；不拦截全页方向键。现有缩放、旋转按钮继续使用。

## 12. 工程规则和多端交付

Biome 已有关键 correctness/suspicious 规则，不是没有 lint。先以当前 2.5.11 schema 逐组启用有价值的规则并收集诊断，清理后再转阻断；推荐规则不要与核心业务迁移同时全面开启。Effect 依赖问题要核实时序，不能为消除警告编造注释或禁用规则。[Biome 配置文档](https://biomejs.dev/reference/configuration/)

formatter 单独小批试点，明确缩进/分号/换行，排除生成物和受保护输入；启用 formatter 后 CI 不能仍只有 `biome lint`，需增加实际格式检查。预提交只检查本批相关文件，CI 作最终门禁；不全仓自动修复后混入业务变更。

CI 和 Web Docker 已 Node 24，当前本机为 24.14.0。补 engines 和本机版本文件，具体 patch 以实际验证版本维护；继续 npm ci 和现有 audit，不重复建立另一套依赖审计，不顺带更换包管理器。

多端边界：Web 管理端承担平台/学校管理和教师体验；学生端只读取本人已发布成绩并处理学生交互；Desktop 承担扫描、离线队列及现有阅卷草稿，不缩成只有扫描。Web 的 student experience 当前是学生入口提示，不是第二套成绩业务。

teacher-portal/auth-client 保留预留说明即可；有独立发布节奏、用户流程和明确负责人时再建设。shared-types 小而有用，按真实依赖决定归属。

学生端单独列部署核对：静态站与代理、VITE_STUDENT_PORTAL_URL、登录回跳、cookie 域/路径、本人范围、已发布版本和申诉隔离。主 Compose 的独立学生站点装配需在部署阶段核验，不能仅因源码端存在就认为可交付。

## 13. 实施批次、交付物与估算

工时为阅读当前代码后的工程估算，不是承诺。假设一位熟悉项目的前端工程师、已有基线可验证且没有同时变更核心接口；人日包含针对性测试和评审，不包含大规模真实环境准备。批次按依赖推进，不必等待所有治理才发布。

| 批次 | 内容 | 交付物 | 估算人日 | 前置 |
| --- | --- | --- | ---: | --- |
| A0 | 保存基线、校正 7 条门禁、规则覆盖清单 | 可解释且可信的门禁、现状清单 | 1–2 | 无 |

| A2 | 学校助手与 PDF lazy、占位、体积基线 | 依赖图、五场景测量、性能改动 | 2–4 | A0，可与 A1 并行 |
| A3 | 快捷键/查看器键盘/答案分组交互与校准重点测试 | 可操作交互、风险场景测试 | 3–5 | A0 |
| B1 | 3–5 路由试点，确有需要再抽 AuthProvider | 路由职责决议、试点与深链/离开回归 | 4–6 | A1，选定收益目标 |
| B2 | 选一项只读 Query 或区域组合试点，controller 按耦合决定 | 试点证据及清楚的业务状态 | 3–5 | A1，存在具体维护成本 |

第一轮建议先完成 A0–A3，约 9–16 人日；A1/A2 可分工并行。之后按路由试点和测量结果决定扩大范围。C2 按 API 域另行排期，不包含在所谓“几周完成全量 SDK 改造”的保证中。多端部署文档与剩余边缘测试可随相关批次完成。

每批独立提交/评审并可回退：不同时更换路由、草稿写路径、transport 与身份政策。只读 Query 试点可通过服务实现切换回旧路径，但不能让两个实现同时发请求。回退写路径不得丢弃已持久化的 command ID、冻结载荷或已获服务端确认的 revision；若改持久化格式，单独设计兼容。

## 14. 每批统一验收要求

- 所有新增或修改的非直观规则同步补简单中文注释，解释身份作用域、状态边界、顺序、版本和失败恢复；按[代码注释与维护说明标准](../docs/engineering/commenting-standard.md)检查附近旧注释。
- 源码审查记录实际读到的范围；未读文件保留 pending，不能由自动枚举、行数或匹配次数宣称全仓完成。
- 受影响应用 typecheck、构建、相关单测通过；需要权限/导航/复杂交互时跑针对性 E2E。全量检查只在涉及面或失败风险需要时扩大。
- 正式交付继续现有 lint、用户文案、生产路由、授权、架构、schema 和生成契约门禁；共享包增加真实 test 执行入口。
- CSS/阅读字号变更做相关视口视觉验收；性能变更用同环境新构建与网络/Profile 基线验证；mock 测试不表述为真实生产集成保证。
- 与本批无关的原有未提交修改保留。历史 SQL、生成物、锁文件、快照和哈希输入依正式流程维护，不手工补注释或顺带改写。
