1总体优化策略

目标不是“换皮”，而是把一套完成度不错的 AntD 后台，升级为有品牌识别、信息密度可调、高信任、键盘友好的专业阅卷工具。成熟产品的共性经验可归纳为四条主线：

  • 先立“地基”再谈“好看”：Linear、Stripe、Atlassian 的精致都建立在单一数据源的设计令牌之上。先把 token 三层化、主题单点收敛，品牌与暗色才有承载。
  • 为高频路径做极致优化：阅卷是“每天重复上千次”的操作。对标 Linear/Figma 的高密度、键盘流、即时反馈，把每次评分的点击与等待降到最低。
  • 用“信任”设计支撑 AI：AI 给分必须可解释、可追溯、可推翻。对标 Stripe 对数据口径的标注、GitHub 对状态的多通道表达，让老师敢用、能纠错。
  • 把规范变成系统：对标 Atlassian/Carbon/Polaris，组件、文档、用法（Do/Don’t）、可访问性一体化，避免“靠人记住规范”。

主题 A品牌与视觉个性Linear · Stripe · 飞书
现状整体接近“标准 AntD 模板”，主色蓝、卡片白底；登录页简洁但记忆点弱，缺少能一眼认出“这是 EduGrade”的品牌符号与质感。
成熟产品怎么做Linear 的品牌感来自极致排印、微妙边框光与克制动效，而非大 Logo；Stripe 把品牌色只压在关键处、大量中性色衬托；飞书用统一圆角、留白、图标与空状态形成温和专业的中文气质。
EduGrade 落地建议
  • 把品牌主张（建议关键词：准确 · 高效 · 可信赖）转成视觉语言：阅卷强调“精确”，走理性、几何、清晰路线，而非活泼多彩。
  • 统一主蓝：选定 AntD 6 号 #1677ff 为品牌主色，7 号 #0958d9 为 hover/按下，Logo 的 #1667d8 向其对齐，避免“两个蓝”。
  • 登录页升级为左右分屏：左侧品牌叙事（产品价值 + 一张真实阅卷场景或抽象数据纹理），右侧表单；窄屏回落为居中卡片。
  • 图标统一 lucide（已做），定尺寸/描边规范；关键品牌入口可定制；质感用“1px 边框 + 极轻阴影 + 仅 hero/主按钮的微渐变”，禁止大面积渐变滥用。
/* 建议：品牌蓝色阶（Ant Design Blue 公开色阶，6=主色） */
--brand-1:#e6f4ff; --brand-2:#bae0ff; --brand-3:#91caff;
--brand-4:#69b1ff; --brand-5:#4096ff; --brand-6:#1677ff;
--brand-7:#0958d9; --brand-8:#003eb3; --brand-9:#002c8c;
/* soft 浅底统一由色阶浅色派生，不再手写 */
--brand-bg: var(--brand-1);
主题 B色彩系统治理Carbon · Atlassian · Arco
现状蓝（#1677ff）与青（#13c2c2）两套强调色职责不清；存在 #c9363e / #c81424 / #d92d3a 等多个近似红；仅有浅色，无暗色。
成熟产品怎么做Carbon 令牌“跨主题名称不变、只改值”，并有 base/layer01–03 的分层模型；Arco 用 CSS 变量内置亮/暗两套色板、暗色由亮色算法生成；Atlassian surface 亮 #FFFFFF / 暗 #1D2125 成对定义。
EduGrade 落地建议
  • 强调色分工：蓝=全局导航/主操作；青=仅“采集/质检”业务域，其余场景禁用青做强调，写入规范。
  • 红色归并：通用危险/失败 #c9363e，人工推翻用更深的 #c81424；删除 #d92d3a 等临时值。
  • 三层令牌：primitive（原始色值）→ semantic（surface/text/border/状态）→ component；亮/暗只重映射 semantic（详见主题 J）。
  • 暗色模式：服务教师夜间长时间阅卷；色盲友好：图表默认蓝/橙组合（见主题 F），状态=颜色+图标+文字。
/* 建议：暗色语义层（参考 GitHub Dark / Atlassian Dark 成对值） */
--bg-page:#0d1117;   --surface:#161b22;  --surface-raised:#1c2128;
--border:#2a313c;     --text:#e6edf3;     --text-muted:#9aa6b2;
/* 遮罩：对标 Arco #1D2129 @ 60% */
--overlay: rgba(13,17,23,.60);
主题 C字体排版与数字Stripe · GitHub · Linear
现状系统字体栈中文渲染稳妥、零字体加载；正文 14px、行距 1.6；但分数/计数用比例数字，相邻宽度不一、纵向难对齐。
成熟产品怎么做Stripe 数据表用横向分隔线、大写表头、状态码窄列、左对齐，并提供 dense 版；数字用等宽/表格数字。Linear 以字重对比（400 vs 600）建立层级、最多 2 个字体族，密度高仍清晰。
EduGrade 落地建议
  • 数字全局策略：指标、分数、计数、数字列启用 tabular-nums；表格数字列右对齐、单位统一；可仅对数字引入等宽字体。
  • 保留 13/14/16/18/24/26 字号；正文默认 14，配合“舒适/紧凑”密度档；大字模式继续推广。
  • 行高：正文 1.6 / 表格 1.5 / 标题 1.3；字重只用 400/500/600/700。
  • 统一页面标题区：主标题 + 副标题 + 右侧操作区；中西文混排统一间距与数字字体。
/* 建议：数字与排版 */
.num, .stat, td.num {
  font-variant-numeric: tabular-nums;
  font-feature-settings: "tnum" 1;
  text-align: right;
}
/* 仅数字用等宽（系统等宽兜底，无需外部字体） */
--font-num: ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas;
主题 D布局与信息密度Linear · Figma · Jira
现状三栏工作台范式成熟，但质检右栏同屏堆叠环形/七指标/问题/门控/元信息，负荷高；移动端为“堆叠缩放”，图标按钮触控偏小。
成熟产品怎么做Linear 三栏可折叠、并把侧栏调暗让主工作区突出；Figma 左右面板可收起、中央画布最大化；Jira/GitHub 提供 comfortable/compact 密度切换并记忆偏好。
EduGrade 落地建议
  • 三栏标准化：定义各栏宽度区间，左队列可收起、右详情可关闭，中央自适应最大化；记忆用户布局。
  • 密度两档：comfortable / compact（影响行高、内边距），阅卷高强度场景默认 compact。
  • 右栏减负：按“结论 / 分项指标 / 触发问题 / 门控 / 元信息”分组，元信息默认折叠；“结论 + 主操作”sticky 常驻。
  • 移动端定位：监看/轻处理，重操作引导桌面；触控目标 ≥44px（WCAG AAA），最低不小于 24px（AA 2.5.8）。
/* 建议：密度档（compact 用于高强度阅卷） */
:root{ --row-h:44px; --card-pad:20px; }      /* comfortable */
[data-density="compact"]{ --row-h:34px; --card-pad:14px; }
/* 触控热区：图标按钮最小 44×44，间距避免与相邻目标重叠 */
主题 E组件视觉规范Polaris · Atlassian · AntD Pro
现状“轻边框 + 圆角 + 极轻阴影”统一；但同一考试阶段有两套步骤条、空状态都用同一个文件盒线稿、浮层层级弱、长数字串会横向溢出。
成熟产品怎么做Polaris 空状态用于“引导下一步”、Badge 仅 1–2 词且 tone 全局一致；Atlassian 有统一步骤条与 Banner；AntD Pro/Arco Pro 提供页面容器与业务组件模板。
EduGrade 落地建议
  • 步骤条统一：工作台用“横向卡片式步骤”（状态图标、可点击已完成步），窄空间用紧凑圆点版；定 API（currentStep/statuses/onStepClick）。
  • 空状态体系：无任务/无数据/无权限/出错/搜索无结果各一种，含图示 + 一句说明 + 主行动按钮；首次使用加引导或示例。
  • 表格：数字右对齐 + tnum、表头固定、长文本省略 + tooltip、行操作收“更多”、批量操作浮条、加载/空/错误三态。
  • 浮层与防护：统一 floating 阴影与 z-index 层级；长 ID/文本统一换行、截断或横向滚动，杜绝溢出。
/* 建议：浮层阴影（当前阴影过轻，层级靠遮罩） */
--shadow-floating: 0 8px 24px rgba(16,24,40,.12), 0 2px 6px rgba(16,24,40,.10);
--shadow-modal: 0 12px 32px rgba(16,24,40,.18), 0 4px 10px rgba(16,24,40,.12);
/* 长内容防护 */
.cell{ overflow:hidden; text-overflow:ellipsis; white-space:nowrap; }
主题 F数据可视化Vercel · Stripe · Okabe-Ito
现状质量分环形、七维指标条、答卷热区、红色批注定位是强项，直接支撑人工决策；但图表配色未统一、无数据态与口径说明不足。
成熟产品怎么做Vercel 指标卡 = 大数字 + sparkline + 状态；Stripe 图表与表格联动、时间范围、首页可自定义 widget，并标注“估算/口径”；色盲安全首选 Okabe-Ito 色板与蓝橙组合，顺序数据用 viridis/cividis。
EduGrade 落地建议
  • 统一图表主题：一套基于 token 的 ECharts/recharts theme（色板、网格线、字号、tooltip、空态），全局共用。
  • 指标卡标准：大数字（tnum）+ 标签 + 同比/环比（方向箭头）+ sparkline，点击下钻。
  • 环形质量分：中心分值 + 等级，A 绿/B 蓝/C 橙/D 红固定映射并配图例，标注计算口径。
  • 热区联动：问题列表与热区互相定位（点问题跳到热区，对标 Figma 图层-画布）；AI 结论标注“AI 生成，需人工确认”。
/* 建议：色盲安全分类色（Okabe-Ito/Wong，三类色觉障碍下可区分） */
--cat: #0072B2 /*蓝*/, #E69F00 /*橙*/, #009E73 /*蓝绿*/,
        #D55E00 /*朱*/, #CC79A7 /*粉紫*/, #56B4E9 /*天蓝*/;
/* 状态不仅靠颜色：直接标注 + 不同形状标记 */
主题 G交互反馈与微交互Linear · Notion · Figma
现状具备 toast、确认弹窗、自动保存提示；但加载多为转圈、高频评分存在等待感、快捷键分散且无可视化清单。
成熟产品怎么做Linear 乐观更新（先改本地、后台同步、出错才提示）+ 行/卡形骨架屏；Notion 就地编辑、保存状态常驻可见；Gmail/Figma 危险操作可撤销（undo）、快捷键体系完整。
EduGrade 落地建议
  • 加载三态：页面/卡片用骨架屏（队列用行形、指标用卡形、文档用块形），按钮用 loading，避免白屏与转圈。
  • 乐观更新 + 回滚：评分/标签先更新 UI，失败 toast 并回滚（react-query onMutate 已支持）。
  • Toast：成功轻提示自动消失，错误可读 + 重试，危险操作给“撤销”。
  • 快捷键：J/K 切换、数字键评分、Enter 确认、Cmd+Enter 提交、? 打开速查面板；动效 150–250ms 并尊重 reduced-motion。
/* 建议：阅卷快捷键（对标 Linear/Figma/Gmail） */
J/K      /* 上一份 / 下一份答卷 */
1 2 3 4  /* 评分档位（正确/部分/错误…） */
Enter    /* 确认 AI 建议 */   Cmd+Enter /* 提交本份 */
?        /* 快捷键速查浮层 */  Cmd+K /* 命令面板 */
主题 H导航与信息架构Linear · 飞书 · Slack
现状分组侧栏 + 面包屑基本清晰；但路由双轨（TanStack 占位 + 自研解析，见代码审查 P0），导航高亮/面包屑存在两套来源风险。
成熟产品怎么做Linear/Notion/Vercel 都以 Cmd+K 命令面板为高频入口（fuzzy、分类、最近、内联快捷键、上下文感知）；Slack/飞书 用多级工作区导航与可折叠收藏。
EduGrade 落地建议
  • 命令面板（Cmd+K）：搜考试/答卷/学生、跳转功能、执行命令；打开时显示最近/建议而非空输入，结果内联快捷键。
  • 侧栏分组可折叠、当前项高亮、常用可固定；面包屑显示“平台/学校/考试/题目”。
  • 多答卷可用标签页（tabs）减少来回；提供全局搜索与最近访问。
  • 路由收敛后，高亮与面包屑统一由路由状态派生（与代码 P0 一并解决）。
主题 I可访问性与包容性WCAG 2.2 · Carbon · GitHub
现状已有“跳到主要内容”、focus-visible、大字模式、reduced-motion、主区 tabIndex，基础不错；自定义查看器/快捷键的键盘路径与 ARIA 待补。
成熟产品怎么做WCAG 2.2：文字对比 ≥4.5:1（大字 3:1）、目标尺寸 AA ≥24×24（2.5.8）/AAA ≥44×44（2.5.5）、焦点指示对比 ≥3:1 且达 2px 周长；Carbon/GitHub 提供完整键盘与读屏模式。
EduGrade 落地建议
  • 核对次要文字/图标/图表细线对比度达 AA；焦点保持 2px outline + offset、对比 ≥3:1。
  • 所有操作可键盘完成；弹窗焦点陷阱；自定义查看器支持方向键/缩放，快捷键可查看与关闭。
  • 图标按钮加 aria-label；toast/队列变化用 live region；tabs/dialog/menu 遵循 WAI-ARIA APG。
  • 状态 = 颜色 + 图标 + 文字；支持 200% 缩放不破；预留 i18n 与日期/数字本地化。
主题 J设计系统工程化Carbon · Atlassian · Polaris
现状令牌分层与共享 UI 包底座完整；但 grading.ts/reading.ts 注释编码乱码、--eg 与 antd token 双映射、两处 ConfigProvider、ui 包仅约 6 处使用、缺规范文档。
成熟产品怎么做Carbon 用 primitive→semantic→component 令牌；Atlassian 令牌单点、把设计系统当产品运营，并用便携 DESIGN.md（机器可读 token + 人类可读 rationale）；Arco 遵循“粒子变量→基础组件→复杂组件”。
EduGrade 落地建议
  • 令牌三层并由 design-tokens 单点生成 CSS 变量与 antd 主题，消除双映射、合并为一处 ConfigProvider。
  • 修复乱码、统一 UTF-8；token 版本化 + changelog。
  • ui 包收口基础组件（Button/Badge/Empty/Steps/PageHeader/Stat 等），补用法、Do/Don’t、a11y 与视觉回归；“要么推广要么精简”。
  • 建文档站（Storybook）；Figma token 同步（Tokens Studio）；PR 禁止硬编码 hex；以覆盖率/复用率/axe 审计度量。

3建议新增的“成熟产品标配”

这些功能在 Linear/Stripe/Vercel/飞书等产品中已成为专业用户预期，对阅卷这类高频场景收益显著。

命令面板 Cmd+K搜索 + 跳转 + 执行命令，高频入口统一。
主题 / 密度切换亮·暗·跟随系统；舒适·紧凑两档密度。
可记忆工作台面板宽度、折叠状态、筛选预设随账号保存。
快捷键速查（?）可视化全部快捷键，帮助新手成长为专家。
通知中心 + 待办聚合申诉、待确认、异常集中一处，对标飞书/GitHub。
新手引导 + 示例首次进入用示例答卷走一遍，降低上手门槛。

4落地路线图

遵循成熟产品经验：先打地基（令牌/高频路径），再统一组件与核心体验，最后做品牌与系统治理。

M0 · 0–2 周｜地基
  • 令牌三层 + 主题单点、合并 ConfigProvider
  • 修复乱码、统一 UTF-8
  • 数字 tabular-nums、色彩收敛
  • 骨架屏、floating 阴影、超长内容防护
M1 · 2–6 周｜核心体验
  • 命令面板、快捷键速查
  • 密度 / 主题切换
  • 统一步骤条/空状态/表格/Badge
  • 图表主题、乐观更新 + undo
M2 · 6–12 周｜系统与品牌
  • 组件库推广 + 文档站
  • 暗色模式全量
