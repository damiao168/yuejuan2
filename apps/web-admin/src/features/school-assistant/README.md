# 学校 AI 助手

视觉主张：沿用现有设计 tokens，以清晰的消息区和输入框组织工作，减少固定表单和竞争入口。

内容计划：统一提问 → 按需查询进度 → 自然语言回答 → 可展开来源 → 原业务页面入口。建议问题填入同一输入框，考试上下文可删除。

交互主张：真实回答增量显示；工具用轻量状态变化表达进度；来源按需展开，尊重 reduced-motion。

## 当前边界

- `SchoolConversation` 供独立页面和考试抽屉复用，不区分学校业务与一般问答。
- 模型选择考试检索、考试进度和学生端发布诊断工具；服务器每次检查权限及资源范围。尚无成绩分析、成员等专用工具，也无业务写入。
- 打开模块入口只带考试提示；发送问题后才执行模型及工具。范围由服务端核实，多个考试结果不自动沿用最后一个。
- 业务会话与考试上下文会话只保留内存；完整的一般回复在个人设备按授权指纹保存。公共电脑、附件正文、来源与上下文不落盘。
- 停止、卸载、账号或授权变化会取消请求，迟到的事件不能覆盖新会话。断流没有 done 时不算完成，处理入口禁用。
- 来源使用读取时间、revision 和发布版本，不承诺跨来源同一数据库快照。正式发布仍回到原业务页面重新检查。
- 旧 Panel、Result 与查询 hook 保留兼容，当前页面不挂载固定任务面板。
