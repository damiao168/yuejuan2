# 学校 AI 助手

视觉主张：沿用现有设计 tokens，以清晰的消息区和输入框组织工作，减少固定表单和竞争入口。

内容计划：统一提问 → 按需查询进度 → 自然语言回答 → 可展开来源 → 原业务页面入口。建议问题填入同一输入框，考试上下文可删除。

交互主张：真实回答增量显示；工具用轻量状态变化表达进度；来源按需展开，尊重 reduced-motion。

## 当前边界

- `SchoolConversation` 供独立页面和考试抽屉复用，不区分学校业务与一般问答。
- 模型选择考试检索、考试进度和学生端发布诊断工具；服务器每次检查权限及资源范围。尚无成绩分析、成员等专用工具，也无业务写入。
- 打开模块入口只带考试提示；发送问题后才执行模型及工具。范围由服务端核实，多个考试结果不自动沿用最后一个。
- 业务会话与考试上下文会话只保留内存；完整的一般回复在个人设备按授权指纹保存。公共电脑、附件正文、来源与上下文不落盘。
- PDF 附件仅在浏览器提取文字，不做 OCR，也不发送原始 PDF 页面。每页都必须有可提取文字；任一页没有文字时拒绝整份附件并提示页码，避免扫描页被静默遗漏。真实空白页也按此规则处理，需先删除；扫描内容可改传 PNG/JPEG 图片，或先转换为每页带文字层的 PDF。
- 联网开关代表允许搜索。服务端判断本轮应直接回答、澄清、查询校内数据还是搜索公开资料；转入校内问答时先返回业务标记，即使随后中断，回复也不能标作公开历史。公开上下文只承接连续且明确标记的问答（最多六轮、历史一万二千字），普通聊天、附件和校内查询都在前端 API 边界截断。
- 模型选择实际候选网页后读取正文，界面按真实 `web_fetch` 事件显示进度，并区分正文、摘要及读取时间。网页候选经过证据评估，必要时最多补搜一次；最终来源优先保留回答引用的条目，完全漏写编号时保留已核实资料并说明未逐句标注。界面不重排编号，不显示空来源列表，正文读取仍属于公开工具。
- 同一登录页面内切换栏目或关闭抽屉只卸载视图，账户布局继续接收回复，返回后保留原对话和进度；其他栏目提供返回对话的进度入口。
- 主动停止仅取消所选对话；退出、账户或授权变化销毁账户控制器并取消全部请求，迟到的事件不能覆盖新会话。整页刷新或浏览器关闭仍会断开流，未保存的业务会话和在途内容不能恢复。断流没有 done 时不算完成，处理入口禁用。
- 来源使用读取时间、revision 和发布版本，不承诺跨来源同一数据库快照。正式发布仍回到原业务页面重新检查。
- 旧 Panel、Result 与查询 hook 保留兼容，当前页面不挂载固定任务面板。
